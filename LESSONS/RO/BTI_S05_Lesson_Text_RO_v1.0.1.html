Opt biți de date

Intrare: întreg zecimal u între 0 și 255 inclusiv. Sunt acceptate spațiile de la începutul și de la sfârșitul intrării și zerourile inițiale. Sunt respinse intrarea goală, textul nenumeric, numerele negative, valorile fracționare și valoarea 256.

Binar: exact opt poziții, cu ponderile 128, 64, 32, 16, 8, 4, 2 și 1. Hexazecimal: exact două caractere, cu A–F majuscule; fiecare caracter descrie patru biți, deoarece 16 = 2⁴. 255 = 15 × 16 + 15 → FF.

Complement față de doi (two’s complement): s = u dacă u < 128; s = u − 256 dacă u ≥ 128. Interval cu semn: −128…127. Biții rămân aceiași; se schimbă interpretarea. Prima pondere devine −128.

Bitul de paritate este separat

k = numărul biților 1 din date. Paritate pară: p = k % 2. Paritate impară: p = 1 − (k % 2). Operatorul % dă restul împărțirii. p are valoarea 0 sau 1. Bitul p se adaugă la dreapta celor opt biți de date; cuvântul transmis are nouă biți.

Modificarea unui singur bit sau a unui număr impar de biți schimbă paritatea. Inversarea unui număr par de biți în poziții distincte păstrează paritatea. Verificarea de paritate semnalează nepotrivirea parității, fără a localiza sau corecta eroarea.

Clonați copia proprie și verificați origin

Clonarea (clone) aduce fișierele și istoricul Git într-un director local și configurează legătura numită, de obicei, origin. Pentru această activitate, origin trebuie să indice depozitul propriu.

Metoda

  1. O arhivă ZIP oferă fișierele, dar clonarea pregătește și istoricul Git, și legătura necesară publicării. De aceea lucrați în copia clonată.
  2. Lucrăm în rădăcina depozitului clonat: acolo vedeți direct PROJECT, GUIDES și START.html. Comenzile Git se rulează în terminalul acestui folder.
  3. Verificarea origin înainte de editare previne confuzia dintre sursa comună și destinația propriilor commituri. Identitatea autorului se configurează după ce folderul corect este deschis.

Atenție. Nu folosiți git init într-un folder greșit pentru a face să dispară mesajul. Clona corectă conține deja depozitul și istoricul.

Explicația completă, pas cu pas

Copiați URL-ul corect

În depozitul dumneavoastră de pe GitHub alegeți Code → HTTPS și copiați URL-ul terminat în .git. Verificați numele contului din adresă. Acesta trebuie să fie al dumneavoastră.

Folosiți Git: Clone în VS Code

Deschideți Command Palette cu Ctrl+Shift+P pe Windows/Linux sau Cmd+Shift+P pe macOS. Alegeți Git: Clone, introduceți URL-ul copiat și selectați directorul părinte pregătit. La final alegeți Open pentru folderul creat. Dacă apare întrebarea de încredere, verificați întâi că ați deschis proiectul furnizat în copia dumneavoastră.

Verificați folderul, ramura și destinația

În VS Code trebuie să vedeți direct PROJECT, GUIDES și START.html. Deschideți Terminal → New Terminal și rulați comenzile, câte una:

git status

git branch --show-current

La început vă așteptați la ramura main, o stare locală curată și adresa dumneavoastră la origin, pentru fetch și push. origin este un nume local pentru remote, nu numele utilizatorului și nici o dovadă a autentificării.

Configurați autorul numai pentru acest repository

În același terminal, înlocuiți textele din ghilimele cu numele și emailul alese, apoi rulați:

git config user.name "Numele ales"
git config user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --get user.name

Primele două comenzi nu afișează de obicei nimic la reușită; ultimele două arată valorile. Fără --global, configurația se aplică numai acestui repository. Ea nu schimbă contul autentificat pentru push.

Rezolvați o confuzie de folder înainte de editare

Dacă git status spune not a git repository, deschideți prin File → Open Folder folderul clonat, nu părintele lui. Dacă origin arată șablonul comun, ați clonat sursa; deschideți propria copie într-un folder separat. Nu continuați presupunând că push-ul va găsi automat destinația potrivită.

Dintr-un octet în două cifre hexazecimale

O cifră hexazecimală reprezintă patru biți. Un octet de opt biți se poate scrie prin două cifre: prima are ponderea 16, iar a doua ponderea 1.

Metoda

  1. Baza 16 folosește cifrele 0…9 și literele A…F. În aplicație alegem majuscule pentru o afișare uniformă.
  2. Pentru un întreg u între 0 și 255, scriem u = 16q + r, cu q și r între 0 și 15. Cele două cifre corespund lui q și r.
  3. Această regulă vă permite să verificați rezultatul fără să îl copiați din program. Legătura cu binarul este directă: grupați biții în două grupuri de câte patru.

Atenție. Lungimea și valoarea sunt condiții diferite. Un șir cu două caractere poate avea lungimea corectă și să reprezinte totuși alt număr.

Explicația completă, pas cu pas

De ce sunt suficiente două cifre

Două poziții în baza 16 oferă 16 × 16 = 256 combinații. Acestea acoperă exact cele 256 de valori ale unui octet fără semn, de la 0 la 255 inclusiv. Două cifre hexazecimale nu înseamnă doi biți: fiecare cifră reprezintă patru biți.

Calculați cifra din stânga și cifra din dreapta

Exemple suplimentare de conversie
uDescompunere în baza 16Cifrele rezultateBinar pe opt biți
3131 = 16 × 1 + 151F00011111
160160 = 16 × 10 + 0A010100000
254254 = 16 × 15 + 14FE11111110

Numerele din descompunere sunt valori zecimale; în coloana rezultat, fiecare este înlocuit prin cifra corespunzătoare din baza 16.

Verificați prin grupuri de patru biți

Pentru 160, separați 10100000 în 1010 | 0000. Primul grup corespunde cifrei A, al doilea cifrei 0; obțineți A0. Pentru 254, 1111 | 1110 dă FE. Separarea este o metodă de verificare, nu o schimbare a biților.

Reconstruiți valoarea

Verificați în sens invers: pentru A0, valoarea este 10 × 16 + 0 = 160; pentru 1F, 1 × 16 + 15 = 31. Dacă valoarea reconstruită diferă de intrare, conversia este greșită, chiar dacă rezultatul are două caractere.

-  return null;

Fără să consultați un răspuns nou, răspundeți: „Pentru un întreg valid din intervalul 0–255, u.toString(16) îndeplinește singur cerința de exact două caractere hexazecimale majuscule?” Scrieți da sau nu și alegeți două intrări care ar putea deosebi afirmația de cerință.

Nu este o a doua implementare obligatorie și nu înlocuiește testele S05. Este un mod scurt de a decide dacă o sugestie sună plauzibil sau chiar corespunde contractului funcției.

Rezolvarea — deschideți după încercarea dumneavoastră

Trei prompturi din care alegem unul

După încercarea proprie puteți folosi Gemini gratuit, dacă aveți acces. Alegeți un singur prompt și adaptați partea despre predicția dumneavoastră. Nu este nevoie să trimiteți întregul proiect.

Am o funcție care primește un întreg valid între 0 și 255 și trebuie să întoarcă exact două caractere hexazecimale majuscule. Cred că [scriu predicția mea]. Explică-mi dacă toString(16) este suficient și propune două cazuri prin care să verific afirmația, fără să îmi scrii funcția completă.
Am salvat o editare după ce selectasem deja fișierul pentru commit. Eu cred că [scriu ce cred că intră în commit]. Explică-mi ce ar compara git diff și git diff --cached în această situație. Aș vrea să verific explicația, nu doar să memorez comenzi.
Testele S05 sunt verzi. Eu cred că acest lucru dovedește [scriu concluzia mea]. Ce susțin efectiv aceste rezultate și ce concluzii despre autor, publicare sau cazuri neverificate ar depăși observația?

Alternativa pregătită este un exemplu didactic

Afirmație pregătită pentru verificare, nu citat din Gemini: „Conversia cu toString(16) este suficientă, deoarece am obținut un text în baza 16.” Alegem intrările 0 și 31. Pentru contractul aplicației așteptăm 00 și 1F. Numai conversia produce 0 și 1f.

Prima intrare arată diferența de lungime; a doua arată diferența dintre litere mici și majuscule. Afirmația confundă scrierea în baza 16 cu formatarea exactă cerută. Un singur contraexemplu ar fi suficient să o infirme; cele două ne arată două aspecte diferite ale cerinței.

Păstrați concluzia și închideți instrumentele AI înainte de test

Dacă ați folosit clarificarea, puteți nota scurt afirmația verificată și concluzia în propriile însemnări S05. Nu se cere conversația, captură sau alt fișier. Rezultatul important este să puteți explica ce caz ați ales și ce anume a arătat.

La Q05 folosirea Gemini, a altui AI sau a ajutorului colegilor nu este permisă. Referința comună deja anunțată rămâne permisă. Trecem de la sprijinul pentru învățare la verificarea individuală.

Legătura cu pasul următor. Încheiem pregătirea și intrăm în Q05, păstrând numai resursa permisă.

În întrebările hexazecimale Q05, literele mici sunt acceptate alături de majuscule. Acest lucru nu schimbă cerința programului: toHex8 trebuie să întoarcă exact două caractere majuscule. Modul în care se recunoaște un răspuns la test și contractul unei funcții software sunt reguli diferite.
