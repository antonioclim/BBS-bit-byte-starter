Eight data bits

The input is a decimal integer u from 0 to 255 inclusive. Leading and trailing spaces are ignored; leading zeros are accepted. Empty input, text, negatives, fractions and 256 are rejected. The eight binary positions have weights 128, 64, 32, 16, 8, 4, 2, 1.

One hexadecimal digit represents four bits because 16 = 2⁴. Therefore a byte needs exactly two hexadecimal characters, including a leading zero where required. Digits 10–15 are A–F. For example, 5 → 00000101 → 05 and 255 = 15 × 16 + 15 → FF.

For eight-bit two’s complement, interpret the same pattern as s = u for 0 ≤ u < 128, or s = u − 256 for 128 ≤ u ≤ 255. The range is −128 to 127. The leftmost bit has weight −128 in this interpretation; the stored bits do not change.

One separate parity bit

Let k count the 1 bits in the eight data bits. Append a numeric bit p at the right. A · even: p = k % 2, making k + p even. B · odd: p = 1 − (k % 2), making k + p odd.

The transmitted display has nine bits: eight data bits plus a separate check bit. A single bit flip changes parity; any odd number of flips does so. An even number can preserve it. A parity check does not locate or correct the error.

8/23 · 04 · A requirement becomes code · 32:00–37:00

From a byte to two hexadecimal digits

One hexadecimal digit represents four bits. An eight-bit byte can be written with two digits: the first has weight 16 and the second has weight 1.

Method

  1. Base 16 uses digits 0…9 and letters A…F. The application requires uppercase letters for a consistent display.
  2. For an integer u between 0 and 255, write u = 16q + r, with q and r between 0 and 15. The two digits correspond to q and r.
  3. This rule lets you check the result without copying it from the program. The connection with binary is direct: split the bits into two groups of four.

Watch out. Length and value are separate conditions. A two-character string can have the correct width while representing the wrong number.

Complete explanation, step by step

Why two digits are sufficient

Two positions in base 16 provide 16 × 16 = 256 combinations. They cover exactly the 256 unsigned byte values from 0 to 255 inclusive. Two hexadecimal digits do not mean two bits: each digit represents four bits.

Calculate the left and right digits

Additional conversion examples
uBase-16 decompositionResulting digitsEight-bit binary
3131 = 16 × 1 + 151F00011111
160160 = 16 × 10 + 0A010100000
254254 = 16 × 15 + 14FE11111110

The numbers in the decomposition are decimal values; in the result column, each is replaced by its corresponding base-16 digit.

Check using groups of four bits

For 160, split 10100000 into 1010 | 0000. The first group corresponds to digit A and the second to 0, giving A0. For 254, 1111 | 1110 gives FE. Splitting is a checking method and does not change the bits.

Reconstruct the value

Check in reverse: for A0, the value is 10 × 16 + 0 = 160; for 1F, it is 1 × 16 + 15 = 31. If the reconstructed value differs from the input, the conversion is wrong even if the result has two characters.

Specify the toHex8 contract

toHex8 receives a validated integer in 0…255 and returns a string of exactly two uppercase hexadecimal characters. Preserve the validateByte(u) call.

Method

  1. The contract specifies what the function should receive and produce. Distinguish interface text from the number passed to the function.
  2. Input validation is already supplied. The S05 change should provide a result for valid inputs without weakening rejection of invalid arguments.
  3. We use a string because formatting is part of the result: leading zeroes and uppercase letters must be preserved exactly.

Watch out. Do not remove validation merely because the application filters input. The function is also tested directly with invalid numeric arguments.

Complete explanation, step by step

Interface input and function argument

In the application enter a decimal integer between 0 and 255. parseByte converts valid text to a number. Surrounding spaces and leading zeroes are accepted; notation 0xFF is not a decimal input accepted by this field. toHex8 receives the resulting number rather than the field’s text.

Output conditions

The toHex8 function contract

Result typeA string rather than a number.

The name toHex8 refers to representing an eight-bit byte; the hexadecimal output has two characters, rather than eight.

Correct value and incomplete format

For input 5, string "5" does not satisfy the length requirement, while number 5 also fails the result-type requirement. For input 255, string "ff" has the right value and length but lacks the required uppercase letters. The contract requires every condition to hold.
