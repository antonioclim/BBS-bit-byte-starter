Eight data bits

The input is a decimal integer u from 0 to 255 inclusive. Leading and trailing spaces are ignored; leading zeros are accepted. Empty input, text, negatives, fractions and 256 are rejected. The eight binary positions have weights 128, 64, 32, 16, 8, 4, 2, 1.

One hexadecimal digit represents four bits because 16 = 2⁴. Therefore a byte needs exactly two hexadecimal characters, including a leading zero where required. Digits 10–15 are A–F. For example, 5 → 00000101 → 05 and 255 = 15 × 16 + 15 → FF.

For eight-bit two’s complement, interpret the same pattern as s = u for 0 ≤ u < 128, or s = u − 256 for 128 ≤ u ≤ 255. The range is −128 to 127. The leftmost bit has weight −128 in this interpretation; the stored bits do not change.

One separate parity bit

Let k count the 1 bits in the eight data bits. Append a numeric bit p at the right. A · even: p = k % 2, making k + p even. B · odd: p = 1 − (k % 2), making k + p odd.

The transmitted display has nine bits: eight data bits plus a separate check bit. A single bit flip changes parity; any odd number of flips does so. An even number can preserve it. A parity check does not locate or correct the error.

4/23 · 02 · From requirement to prediction · 10:00–13:00

The requirement: one separate bit for the assigned mode

Implement only the assigned mode in parityBit8(u, mode): A means even parity and B means odd parity. The function receives a validated number and returns the number 0 or 1.

Method

  1. Count the 1 bits in the eight data bits and choose one extra bit so that the total has the required parity.
  2. The interface appends the bit on the right. The resulting word has nine bits: eight data bits and one check bit. A byte still consists of eight bits.
  3. Preserve validation, completed functions and the unassigned mode. A/B is your project requirement; it does not override the mode specified by a Q07 item.

Watch out. The parity of the decimal input is not the number of 1 bits in its representation.

Complete explanation, step by step

Record the assigned mode

At the start of the S07 section in PROJECT/evidence.md, write Variant A — even or Variant B — odd as assigned in class. Select that same mode in the application and test page. Do not later choose whichever mode happens to produce green results.

Distinguish data, one-bit count and check bit

Let k be the number of 1 bits in the data and p the extra bit. k ranges from 0 to 8 whereas p is only 0 or 1. For A, the total k + p must be even; for B, it must be odd. Count 1 bits rather than using the decimal data value.

What the function preserves and the interface builds

parityBit8 neither changes the byte u nor returns a nine-character string. It returns only the numeric bit. The interface then combines the eight bits from toBinary8(u) with this bit. Signed interpretation remains the separate function fixed in S06.

Why the boundary matters

A small requirement becomes easy to check when inputs, outputs and each function’s responsibility are explicit. In Q07 you can explain the distinction between data and control. In other projects, the same discipline prevents new functionality from accidentally changing established formats or behaviour.

An analogous example: how many boxes of eight items are needed?

A supporting example, with no additional task. We have an already validated integer count of items from 0 to 255; a box holds at most eight. First calculate the full boxes; the remainder tells you whether one more is needed. The problem asks for a box count, rather than a parity bit.

function boxesNeeded(itemCount) {
  const fullBoxes = Math.floor(itemCount / 8);
  const extraBox = itemCount % 8 === 0 ? 0 : 1;
  return fullBoxes + extraBox;
}

For 16 items there are two full boxes and no remainder: the result is 2. For 19 there are two full boxes and a remainder of 3: the result is 3. For zero items the result is 0. Follow the sequence: intermediate value → decision from the contract → numeric result.

The fragment can be evaluated separately in JavaScript, but do not paste it into PROJECT/lab.js or commit it to the project. In S07, another function supplies the count, the criterion concerns the parity of the total and the result is only 0 or 1. The box rule does not solve that task.

14/23 · 05 · Check the result and its limits · 46:00–50:00

What can the parity bit reveal?

A check has a specific purpose. Compare words of the same length and investigate what happens when bits in the transmitted word are flipped.

Method

  1. Keep the established convention: eight data bits followed by a parity bit on the right. The transmitted word has nine bits.
  2. Predict the outcome before reading the explanation. A flipped bit changes from 0 to 1 or from 1 to 0 at a specified position.
  3. Separate detecting a mismatch from locating and correcting an error. Establish what each example permits you to conclude.

Watch out. Do not call the nine-bit word a byte or treat passing parity as complete message integrity.

Predict three changes to the same word

For data 00000011, start from the valid word for your variant: A — 000000110; B — 000000111. The last bit is the check bit. Without calculating a replacement parity bit, imagine flipping the first data bit, the first two data bits and only the last bit. Will the check accept each received word? Record your prediction and reason before revealing the explanation.

Answers — open after your attempt

Flipping one data bit changes the total

One flipped data bit, the same expected parity

A — even0000001101000001103Odd: a mismatch is detected.

Check the received word against the known convention. Do not calculate and replace its received check bit: that would conceal the change you are investigating.

Flipping two distinct bits preserves parity

Two flips, a different word that passes the check
VariantSent wordReceived word1 bits receivedCheck
A — even0000001101100001104Even: accepted although the data differ.
B — odd0000001111100001115Odd: accepted although the data differ.

The two positions are distinct. Each flip changes parity, so the second changes it back. Acceptance does not establish that the received word is identical to the sent word.

The check bit can also be flipped

Flipping only the check bit
VariantSent wordReceived word1 bits receivedCheck
A — even0000001100000001113A mismatch is detected.
B — odd0000001110000001102A mismatch is detected.

The check cannot establish whether a data bit or the check bit changed. Several different positions could produce the same parity mismatch.

State the limit precisely

In this model, for a nine-bit word and flips at distinct positions, every odd number of flips changes parity and is detected. Every even number of flips preserves parity and passes this check. Simple parity neither locates nor corrects the error. We have not analysed insertions, deletions or other changes of length here.

Compare your prediction with the three cases. Revising a prediction after checking it shows what you learnt; keep a precise explanation rather than the overstatement “parity detects every error”.
