Eight data bits

The input is a decimal integer u from 0 to 255 inclusive. Leading and trailing spaces are ignored; leading zeros are accepted. Empty input, text, negatives, fractions and 256 are rejected. The eight binary positions have weights 128, 64, 32, 16, 8, 4, 2, 1.

One hexadecimal digit represents four bits because 16 = 2⁴. Therefore a byte needs exactly two hexadecimal characters, including a leading zero where required. Digits 10–15 are A–F. For example, 5 → 00000101 → 05 and 255 = 15 × 16 + 15 → FF.

For eight-bit two’s complement, interpret the same pattern as s = u for 0 ≤ u < 128, or s = u − 256 for 128 ≤ u ≤ 255. The range is −128 to 127. The leftmost bit has weight −128 in this interpretation; the stored bits do not change.

One separate parity bit

Let k count the 1 bits in the eight data bits. Append a numeric bit p at the right. A · even: p = k % 2, making k + p even. B · odd: p = 1 − (k % 2), making k + p odd.

The transmitted display has nine bits: eight data bits plus a separate check bit. A single bit flip changes parity; any odd number of flips does so. An even number can preserve it. A parity check does not locate or correct the error.

3/23 · 02 · The definition before the program · 08:00–12:00

The same bits with different weights

For an eight-bit two’s complement value, the first bit has weight −128 and the remaining weights are 64, 32, 16, 8, 4, 2 and 1. Changing the interpretation does not change the bits.

Method

  1. The application input remains an unsigned decimal integer from 0 to 255. The signed output interprets those eight bits; it is not a different input required from the user.
  2. Calculate the expectation without asking the program. This lets you recognise an incorrect displayed result.
  3. The piecewise rule is useful in code; the weights explain why the rule is correct.

Watch out. Two’s complement describes an interpretation at a fixed bit width. It does not make every displayed conversion result automatically correct.

Complete explanation, step by step

Compare the weights of the eight positions

Add a weight only when the bit in that position is 1. The changed weight of b7 makes the difference.

One case from each half

Two examples calculated from the weights

For 192 retain the string 11000000. Do not rewrite it to produce −64; read the same bits with different weights.

Why subtract 256?

When the first bit is 1, its contribution changes from +128 to −128. The difference is −128 − 128 = −256. Therefore subtract 256 from the unsigned value. When the first bit is 0, its contribution stays zero and the value is unchanged.

The rule and the output range

Rule: s = u for 0 ≤ u < 128; s = u − 256 for 128 ≤ u ≤ 255. The signed result is in −128…127. The function receives an already validated number; do not weaken validation to repair interpretation.
