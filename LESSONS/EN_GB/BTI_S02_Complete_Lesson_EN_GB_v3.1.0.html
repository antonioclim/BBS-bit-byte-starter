Open the continuous reading copy

What we will learn

  • Distinguish a bit pattern from the value it represents in a declared format.
  • Encode and decode eight-bit integers as unsigned, sign and magnitude, one's complement and two's complement values.
  • Recognise a value outside the representable range and distinguish overflow from a binary carry.
  • Convert binary fractions and represent values using eight-bit two's complement with four fractional bits.
  • Apply an explicit rounding rule, calculate the error and check the range.
  • Construct and check an example of a normal binary32 number.

Why this will help

  • Explain why a byte displays a different value when its format changes.
  • Choose tests that check the value, the limits and the representation convention.
  • Understand when a numerical difference comes from rounding and when a result must be rejected.

What to retain after the steps fade

  • Bits alone do not identify the format: declare the width, sign convention and scale.
  • With eight bits: unsigned 0…255; two's complement −128…127; one's complement and sign and magnitude −127…127.
  • In two's complement, when the first bit is 1: the value is U − 2ⁿ, with the width n declared.
  • Fixed point: encode the scaled integer and check the value after decoding.
  • Floating point: check the sign, exponent, fraction and category of the number.
  • Your explanation must include the convention, calculation, check and limits.

Reading bits requires a convention. The core route uses eight-bit integers, eight-bit fixed point with four fractional bits and normal IEEE 754 binary32 numbers. Supplements are marked separately.

01 · In the seminar · 0–8 min

S02 · What do these bits mean?

A bit pattern acquires a value only after we specify the format: width, sign convention, position of the fractional part or encoding rule.

Why this method works

In S01 we changed the base without changing the value. Now we keep the bits and change the reading convention. This explains why two programs can display different values for the same byte.

Steps to follow

  1. Start with the eight bits without immediately assigning a number to them.
  2. Read the convention required by the question; write it beside your result.
  3. Solve the problem by hand, check it by reconstructing the bits, then use the tool. We follow the core route in 90 minutes; consult the supplements separately.
Choose the rule before calculating

For 10000001, the unsigned reading gives 128 + 1 = 129. The two's complement reading gives −128 + 1 = −127. No bit has changed: the weight of the first bit has changed.

By the end, you will be able to explain differences like these, represent a fraction in a chosen format and reject a result that does not fit. Exercises in the lesson provide local feedback; they do not send answers to Moodle or award seminar points.

A mistake to avoid: A pattern that begins with 1 is not automatically negative: we need to know the format.

In S05–S07 we will state the convention before checking a result; this seminar builds that habit.

02 · In the seminar · 0–8 min

Format and value are different things

Eight bits allow 256 distinct patterns. What each pattern represents depends on the convention, not just on the number of positions.

Why this method works

A byte can represent an integer or a fraction. Mixing these meanings can produce a flawless calculation for a different question.

Steps to follow

  1. Write down the width: here, exactly eight positions.
  2. Separate the question “which bits do we have?” from “how do we interpret them?”.
  3. Check each reading against the format rule; do not automatically convert every pattern into an unsigned integer.

The check differs for each row: 55 in binary gives 00110111 and 3.4375 × 16 gives the scaled integer 55. Choosing the wrong format changes the answer, even when the bits have been copied correctly.

Try before opening the answer

As an unsigned eight-bit integer, what value does 00110111 have? Write the decimal integer.

Answer and verification

55

The active weights are 32, 16, 4, 2 and 1; their sum is 55.

A mistake to avoid: Do not read a fractional format as an unsigned integer; state the scale before calculating.

This distinction helps us check a project requirement before checking its algorithm.

03 · In the seminar · 8–32 min

Unsigned eight-bit integers

The unsigned eight-bit range is 0–255. All weights are positive: 128, 64, 32, 16, 8, 4, 2 and 1.

Why this method works

The width imposes a real limit. A result of 256 cannot be stored in one byte as an unsigned integer, even when the mathematical operation is correct.

Steps to follow

  1. Check whether the value is between 0 and 255, inclusive.
  2. Convert it and add leading zeroes until you have eight bits.
  3. Recalculate the sum of the weights. If a ninth position is needed, report that the value is outside the range.

04 · In the seminar · 8–32 min

Sign and magnitude: separate the sign from the absolute value

In eight-bit sign and magnitude, the first bit indicates the sign and the remaining seven represent the absolute value. The range is −127…127 and there are two codes for zero.

Why this method works

This convention is easy to read, but addition does not work as it does for an ordinary binary integer. Understanding it prevents us from applying the two's complement rule to a different format.

Steps to follow

  1. Write the absolute value in seven bits; the maximum is 127.
  2. Place 0 at the front for positive or 1 for negative.
  3. When decoding, read the sign and the seven magnitude bits separately, then check the absolute value.

00000000 represents +0 and 10000000 represents −0. These are two patterns with the same mathematical value. −128 is unavailable: seven magnitude bits can represent at most 127.

Encode −5 using sign and magnitude with exactly eight bits.

Answer and verification

10000101

The magnitude 5 is 0000101; the first bit 1 indicates the minus sign.

A mistake to avoid: The first bit is a separate sign, not a weight of −128.

When checking a question, the convention determines the encoding method.

05 · In the seminar · 8–32 min

One's complement: invert every bit

In one's complement (C1), obtain the negative of a value by inverting all bits of the positive representation at the same width. Eight bits give −127…127 and two codes for zero.

Why this method works

Inverting the bits is different from adding a sign bit. Next we will compare three negative representations of the same value.

Steps to follow

  1. Represent the positive magnitude with exactly eight bits, beginning with 0.
  2. For a negative value, change every 0 to 1 and every 1 to 0.
  3. Check the negative code by inverting it again: you should recover the magnitude.
−13 in one's complement

00000000 is +0. Inverting it gives 11111111, the code for −0. For a negative code, if U is its unsigned reading, the one's complement value is U − 255: here, 242 − 255 = −13. This formula provides an independent check.

Try before opening the answer

Encode −5 in one's complement using exactly eight bits.

Answer and verification

11111010

+5 = 00000101; inverting every position gives 11111010.

A mistake to avoid: Do not add 1 after inversion in one's complement; that step belongs to two's complement.

Set the width before inverting the bits, otherwise you obtain a different code.

06 · In the seminar · 8–32 min

Two's complement: a single zero

In eight-bit two's complement (C2), the range is −128…127. The first bit has weight −128 and the others have positive weights. There is a single code for zero.

Why this method works

Two's complement allows arithmetic using the same addition circuits, but its range is still limited. A convenient calculation method does not remove the possibility of overflow.

Steps to follow

  1. For a negative value whose positive magnitude fits, write the magnitude in eight bits.
  2. Invert all bits and add 1, retaining eight positions. For the limit −128, use 10000000 directly.
  3. Check either using the weights with −128 or by reading U as unsigned and calculating U − 256 when the first bit is 1.

For zero, inverting 00000000 produces 11111111. Adding 1 produces a carry and eight zeroes. The zero code is still 00000000. For −128, the rule U − 256 checks 128 − 256 = −128 without requiring us to represent +128 as a positive two's complement number.

Try before opening the answer

Encode −5 in two's complement using exactly eight bits.

Answer and verification

11111011

Invert 00000101 and add 1: 11111010 + 1 = 11111011; 251 − 256 = −5.

A mistake to avoid: Do not invert only the lower seven bits or forget the +1 step.

Two's complement is one convention we will need to state when testing a result.

10000001: four correct answers, four conventions

The same pattern can have several correct interpretations. The answer becomes definite only after we choose the convention.

Why this method works

This is a useful test of understanding: start your calculation from the format, not from the first familiar answer.

Steps to follow

  1. Keep exactly the pattern 10000001 in every row.
  2. Apply each definition separately: positive weights, sign and magnitude, one's complement inversion or the negative weight in two's complement.
  3. To check, encode each value again using its row's convention; you should return to the same eight bits.

08 · In the seminar · 8–32 min

Overflow: 127 + 1

Check the mathematical result against the format's range. In eight-bit two's complement, 128 does not fit; the retained pattern 10000000 reads as −128.

Why this method works

A program may continue its calculation with an eight-bit pattern. The existence of a resulting pattern does not prove that it represents the required mathematical sum.

Steps to follow

  1. Calculate the mathematical sum: 127 + 1 = 128.
  2. Add the bits and retain the raw result in eight positions.
  3. Decode it using the original convention and compare it with the sum. Two positive values producing a negative code indicate two's complement overflow.
  4. Repeat the comparison for −1 + 1: there is a carry out, but the value 0 is correct in two's complement. Explain why the two examples have different verdicts.
The same raw calculation, a different verdict by format

Two's complement overflow does not require a final carry. In 127 + 1, carries reach the sign bit and change the interpretation. For −1 + 1, 11111111 + 00000001 leaves 00000000 after discarding the carry out: the result 0 is correct and there is no two's complement overflow.

Try before opening the answer

In eight-bit two's complement, is the mathematical result of 127 + 1 representable? Answer exactly yes or no.

Answer and verification

no

128 exceeds the maximum 127; 10000000 decodes as −128.

A mistake to avoid: Carry and overflow answer different questions; do not substitute one for the other.

After the point: weights 1/2, 1/4, 1/8…

In the fractional part of a binary number, the positions have weights 2⁻¹, 2⁻², 2⁻³ and so on. Use a decimal point in the calculations and inputs in this lesson.

Why this method works

Not every decimal fraction has a finite binary representation. We start with an exact example to keep conversion separate from rounding.

Steps to follow

  1. Write the weight below each bit after the point.
  2. Add only the weights of positions whose bit is 1.
  3. Check the value using an exact fraction or by reconstructing the number.

10 · In the seminar · 32–56 min

Converting a fraction: multiply repeatedly by two

When converting a fraction in [0, 1), each multiplication by two produces the next bit as its integer part. Continue with the remaining fractional part, keeping the same order.

Why this method works

In S01 we read division remainders in reverse order. For fractions, write the bits produced by multiplication directly in step order; reversing them changes the result.

Steps to follow

  1. Multiply the fraction by 2 and record the integer part, 0 or 1.
  2. Keep the fractional part for the next step. Stop when it becomes zero or when you reach the declared precision.
  3. Check the sum of the weights; if you stopped before reaching zero, state that your result is an approximation.

The bits appear in the order 1, 0, 1: 0.625₁₀ = 0.101₂ exactly. The independent check is 1/2 + 0/4 + 1/8 = 5/8. If the original integer part is not zero, convert it separately and join the two parts with the point.

Try before opening the answer

Write 0.375 in binary with exactly three positions after the point and no base subscript.

Answer and verification

0.011

The ×2 steps produce 0, 1, 1; 1/4 + 1/8 = 0.375.

A mistake to avoid: Do not reverse the fraction's bits or use the calculator as an explanation of the method.

This method shows what information a representation loses when its position limit ends the conversion.

Fixed point: eight bits in total, four fractional

Declare the complete format: an eight-bit two's complement integer with four fractional positions. Decode the integer q; the value is q/16. The range is [−8, 7.9375] and the step is 1/16 = 0.0625.

Why this method works

A bit pattern contains no visible point telling us where the fraction starts. The scale is part of the convention. Avoid an ambiguous Q label and state the total number of bits and the number of fractional bits explicitly.

Steps to follow

  1. Read the eight bits as a two's complement integer: q is between −128 and 127.
  2. Divide q by 2⁴ = 16. The weights are −8, 4, 2, 1, 1/2, 1/4, 1/8 and 1/16.
  3. To encode, start from x × 16; if it is not an integer, a rounding rule must be specified.

The reverse check is x × 16 = q. For example, 7.9375 × 16 = 127. Two consecutive codes differ by 1/16; this resolution does not mean that every value within the range can be represented exactly.

In eight-bit two's complement with four fractional bits, encode the scaled integer q = x × 16. For these two values, q is an integer and no rounding is needed.

Separating scaling from sign encoding makes every step checkable. Do not invert the decimal digits of the fraction; work with the integer q.

13 · In the seminar · 32–56 min

Precision, rounding and range validation

Use an explicit rule: round to the nearest integer, with ties going to the even integer. Round q = x × 16, then represent q/16. Here, error means stored value minus requested value. Reject inputs outside the declared range before scaling and check integer q after rounding.

Why this method works

Limited precision introduces a difference even without a programming mistake. We need to be able to say which approximation we chose and why.

Steps to follow

  1. First check x within [−8, 7.9375]; the lesson's policy rejects inputs outside this range.
  2. Calculate x × 16 and identify the two neighbouring integers.
  3. Choose the nearest; if both distances are equal, choose the even neighbour.
  4. Decode the stored value q/16 and calculate the signed error. Under this rule, the absolute error is at most half a step for accepted values.
  5. Before encoding, check q within [−128, 127]. Do not replace validation with saturation or by keeping the last eight bits.
  6. Repeat two checks from the table: decode q = 2 for 0.1 and reject the input 7.95. Explain why an allowed approximation does not replace range validation.

14 · In the seminar · 56–72 min

Floating-point binary32: sign, exponent and fraction

The IEEE 754 binary32 format has 32 bits: one sign bit, eight bits for the stored exponent E and 23 for the fraction F. For normal numbers, the value is (−1)^s × (1 + F/2²³) × 2^(E−127), with E between 1 and 254.

Why this method works

Floating point changes the scale through the exponent. This allows a wide range of values, but precision varies with magnitude.

Steps to follow

  1. Normalise the nonzero number: a single digit 1 before the binary point.
  2. For a normal number, store exponent e + 127 and the bits after the point; the leading 1 is implicit.
  3. Check s, E and F separately. E = 0 and E = 255 have special rules explained in the supplement.
The structure of a normal number

Reconstructed value(+1) × (1 + 0) × 2⁰ = 1

For +1, the pattern is 0 | 01111111 | 00000000000000000000000, or 3F800000 in hex. The 23 bits store the fractional part of the significand, not a standalone decimal fraction. The formula with an implicit 1 applies only to normal numbers.

Try before opening the answer

How many bits does the stored exponent have in binary32? Write the decimal integer.

Answer and verification

8

The format is divided as 1 + 8 + 23 = 32.

A mistake to avoid: Stored exponent E is not actual exponent e; the bias 127 links them.

Communicate the full format before interpreting a 32-bit pattern.

Complete example: 12.5 in binary32

12.5 is exactly representable in binary32. Write it in binary, normalise it and construct the three fields, then check the value and hexadecimal code.

Why this method works

An exact example makes the method visible without adding the rounding problem. Afterwards we can analyse what happens to 0.1 separately.

Steps to follow

  1. 12 = 1100₂ and 0.5 = 0.1₂, so 12.5 = 1100.1₂.
  2. Move the point three positions: 1.1001₂ × 2³. The sign is 0 and E = 3 + 127 = 130.
  3. Store fraction 1001 followed by 19 zeroes, complete all fields and check by decoding.
  4. Cover the final calculation and reconstruct 12.5 from the sign, E and fraction. Only then compare with the tool; the normal form's leading 1 remains implicit.

Integrated exercise: format first, result second

For every answer, state the format and check it by reconstructing the value or the bits. At this stage, work individually, then explain a step to your neighbour.

Why this method works

The aim is not to memorise bit patterns. It is to choose a method, detect invalid input and explain why the check confirms your answer.

Steps to follow

  1. Solve the five local check questions using the required convention and input form.
  2. Before opening the explanation, write down a check calculation for at least two answers.
  3. If an answer does not match, locate the step: format, scaling, sign, width, exponent or rounding. Calculate again.

17 · In the seminar · 82–90 min

What to keep after you forget the details

A good result has four components: the declared convention, calculation, check and limits. A tool can help calculate; it cannot choose the meaning of the requirement for you.

Why this method works

After a few weeks, you may forget a code or a bias. If you keep the method, you can reconstruct them from the format definition without guessing.

Steps to follow

  1. Explain in your own words why 10000001 has four values in our comparison.
  2. Choose a representation and show encoding followed by decoding.
  3. Note what you would check at the range boundary and when a fraction is not exactly representable. Supplements extend the methods without automatically becoming part of the 90-minute route.

Supplement · Entropy is not representation width

Shannon entropy describes the uncertainty of a source with probabilities pᵢ: H = −Σ pᵢ log₂(pᵢ). Use the convention 0 log₂ 0 = 0. Its unit is the bit, but H does not automatically count positions in a byte.

Why this method works

The same unit can appear in two different questions: how many bits a representation occupies and how much uncertainty a random outcome has. Probabilities are essential for the second question.

Steps to follow

  1. Identify the possible outcomes and check the sum of their probabilities: it must be 1.
  2. Calculate a contribution −p log₂p for each outcome; outcomes with probability zero contribute zero.
  3. Add the contributions and interpret H per source outcome without confusing it with the storage space used.
A fair coin and a biased coin
Two sources with the same possible outcomes

0.5 / 0.50.5 × 1 + 0.5 × 11 bit
0.9 / 0.10.9 × 0.152003… + 0.1 × 3.321928…≈ 0.468996 bit

If we store each coin outcome in a byte, we use eight representation bits per outcome in both cases. This does not make the entropy 8 bits. A source that always produces the same outcome has H = 0, even if the file allocates a byte to every outcome.

Do not interpret 0.468996 as a fraction of a position in a particular byte. It measures the average uncertainty of the probabilistic model.

A mistake to avoid: Without a probability distribution, the width of a pattern alone does not determine entropy.

Supplement · Another fixed-point format: 16 bits, eight fractional

Declare a 16-bit two's complement integer with eight fractional positions. The value is q/256, the range is [−128, 127.99609375] and the step is 1/256 = 0.00390625.

Why this method works

The method stays the same when we change the width and scale. However, we must recalculate the range and resolution; do not copy the eight-bit format's limits.

Steps to follow

  1. In 16-bit two's complement, q is between −32768 and 32767. Divide the limits by 256.
  2. To encode, calculate x × 256 and apply the declared rounding rule if needed.
  3. Encode q using exactly 16 bits and check q/256. Do not use a Q-format label without explaining its convention.

Supplement · Binary32: zero, subnormals, infinity and NaN

Fields E = 0 and E = 255 are reserved for special categories. The formula with an implicit leading 1 does not apply to every possible 32-bit pattern.

Why this method works

Without this distinction, we would decode zero and the smallest values incorrectly. An infinite result or NaN is also not a normal number with a very large exponent.

Steps to follow

  1. Examine the stored exponent before inserting an implicit 1.
  2. For E = 0 and F = 0 we have ±0. For E = 0 and F ≠ 0 we have subnormals: (−1)^s × (F/2²³) × 2⁻¹²⁶.
  3. For E = 255, F = 0 indicates ±infinity and F ≠ 0 indicates NaN. Do not apply the normal-number formula.

Supplement · Why 0.1 is not exact in binary32

0.1 has a repeating binary expansion, so it cannot fit exactly into a finite number of fractional bits. Rounded to nearest with ties to even in binary32, its code is 3DCCCCCD.

Why this method works

A small difference between the input and the stored value may be an effect of the format rather than a conversion mistake. State the format and measure the difference.

Steps to follow

  1. Multiply by two to observe the repeating fraction: 0.1 → 0.2 → 0.4 → 0.8 → 0.6 → 0.2.
  2. Normalise: 0.1 = 1.100110011…₂ × 2⁻⁴. Binary32 can keep only 23 bits in the stored fraction.
  3. Decode the rounded code, then compare the exact represented value with 1/10.

Binary64 has 64 bits: one sign bit, 11 exponent bits and 52 fraction bits; its bias is 1023. For normal numbers, the value is (−1)^s × (1 + F/2⁵²) × 2^(E−1023), with E between 1 and 2046.

Supplement · 52 − 21 in one's and two's complement

In eight-bit one's complement, subtract by adding the one's complement of the subtrahend; if a carry out occurs, add it back to the least significant bit. In two's complement, add the two's complement negative and discard the carry out.

Why this method works

These rules differ precisely in how they handle the carry. Comparing them helps us avoid combining steps from two conventions.

Steps to follow

  1. Write both operands at the same width, eight bits, and check the range.
  2. Construct the negative of 21 using the chosen convention; add it to 52.
  3. In one's complement, apply the end-around carry; in two's complement, discard the carry out. Decode the result and check by adding 21.
The same difference, different steps

In one's complement, 52 − 52 produces 00110100 + 11001011 = 11111111, without a carry out. This is the code for −0, so the mathematical value is zero. We can normalise it to +0 only if an explicit policy requires this. In two's complement, the same difference produces 1 00000000 and discarding the carry leaves the single zero code.

This method does not remove the need to check for overflow. For 52 − 21, result 31 fits within both ranges.
