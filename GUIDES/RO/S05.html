Ce veți putea explica la final

Veți avea un depozit Git propriu (repository), o copie locală și prima modificare publicată: afișarea unui octet prin două caractere hexazecimale. Veți putea explica unde se află modificarea după salvare, după înregistrarea locală prin commit și după trimiterea pe GitHub prin push.

Urmăriți pașii de mai jos în timpul activității. Secțiunile cu explicații vă ajută dacă aveți o nelămurire și rămân disponibile după seminar.

Planul celor 90 de minute este orientativ și nu a fost încă verificat cu o grupă. Include activitatea practică, testul individual și recapitularea. Consultați indicațiile suplimentare în etapa căreia îi aparțin.

1 · Creați depozitul propriu pornind de la șablon

Lucrați în browser, pe GitHub. Deschideți șablonul comun BBS-bit-byte-starter. Recunoașteți proiectul: în rădăcină trebuie să existe PROJECT, GUIDES și START.html.

  1. Alegeți Use this template → Create a new repository.
  2. La Owner selectați contul dumneavoastră. Puteți folosi un nume precum bti-byte-lab; dacă grupa are o regulă de denumire anunțată, urmați-o.
  3. Alegeți vizibilitatea indicată pentru grupă. Pentru un depozit privat, linkul nu acordă automat drept de citire altcuiva.
  4. Creați copia numai din ramura implicită; nu cereți includerea tuturor ramurilor.

După creare, antetul și adresa paginii trebuie să arate CONTUL_TAU/REPOSITORY_UL_TAU. Veți publica aici, fără să modificați șablonul grupei. Depozitul este proiectul cu istoricul său; șablonul oferă același punct de pornire tuturor.

Dacă lipsește „Use this template”

Verificați dacă ați deschis linkul indicat, sunteți conectați și aveți acces. Dacă depozitul nu este marcat drept template, cadrul didactic trebuie să verifice pregătirea lui. Nu creați o copie goală ca înlocuitor și nu publicați schimbările în depozitul comun.

2 · Clonați copia proprie în VS Code

În depozitul dumneavoastră de pe GitHub, apăsați Code → HTTPS și copiați URL-ul care se termină cu .git. Acum treceți în VS Code:

  1. Deschideți Command Palette cu Ctrl+Shift+P pe Windows/Linux sau Cmd+Shift+P pe macOS.
  2. Alegeți Git: Clone, introduceți URL-ul copiat și selectați directorul părinte pregătit.
  3. La final alegeți Open pentru directorul clonat. Dacă apare întrebarea despre încredere, verificați întâi că este proiectul furnizat, în copia dumneavoastră.
  4. Deschideți Terminal → New Terminal în rădăcina proiectului și verificați:

Unde se copiază: în terminalul VS Code, din rădăcina depozitului.

git status
git remote -v
git branch --show-current

Trebuie să vedeți ramura main, nicio modificare locală și adresa depozitului dumneavoastră la origin, pentru fetch și push. origin este numele scurt pe care Git îl dă de obicei depozitului de la care ați clonat. Dacă adresa indică șablonul, ați clonat sursa comună; deschideți copia dumneavoastră într-un director separat.

Configurați sau verificați identitatea autorului înainte de primul commit. Pe un cont partajat folosiți numai configurarea locală a acestui repository. Identitatea autorului nu schimbă contul cu care vă autentificați pentru push.

Ce primiți prin clone, față de un ZIP

Clone descarcă fișierele, istoricul Git și legătura origin. Un ZIP oferă fișiere pentru citire, fără să pregătească acest circuit. Pentru lucru deschideți GUIDES/RO/S05.html din copia clonată, ca linkurile către aplicație să folosească același director.

Dacă git status spune „not a git repository”, ați deschis alt director. Folosiți File → Open Folder și alegeți directorul clonat, nu directorul părinte.

Alternativă: clonare din terminal

Folosiți această variantă în locul comenzii Git: Clone. Terminalul trebuie deschis în directorul părinte. Înlocuiți contul și numele depozitului; după comenzi deschideți în VS Code directorul creat.

Unde se copiază: în terminalul VS Code, din directorul părinte ales pentru clonare.

git clone https://github.com/CONTUL_TAU/REPOSITORY_UL_TAU.git
cd REPOSITORY_UL_TAU
git status

3 · Formulați o predicție și rulați proiectul

În VS Code, deschideți PROJECT/evidence.md. La S05 notați ce așteptați pentru 0, 5 și 255: binarul pe opt poziții și hexazecimalul pe două. Scrieți înainte să rulați sau să întrebați Gemini, ca să aveți cu ce compara observația.

Din managerul de fișiere al calculatorului deschideți PROJECT/index.html cu browserul. Din VS Code puteți folosi opțiunea de afișare a fișierului în File Explorer/Finder, apoi îl deschideți. Introduceți numărul zecimal în aplicație: rezultatele se actualizează automat, fără buton de rulare.

Conversia binară este implementată. Afișarea hexazecimală rămâne marcată drept neimplementată până la completarea funcției. Interpretarea cu semn are o problemă pregătită pentru S06, iar paritatea va fi completată în S07. Nu trebuie ca funcțiile viitoare să fie gata astăzi.

Deschideți și PROJECT/tests.html, selectați baseline și apăsați rularea. Aceste verificări privesc funcțiile deja furnizate și trebuie să treacă înainte să editați. Etapele S05–S07 includ cerințe încă neîncheiate.

Introduceți și 256: trebuie respins. Câmpul primește întregi zecimali 0–255, nu 0xFF sau text binar. Spațiile de la capete și zerourile inițiale sunt acceptate, iar golul, textul, fracțiile și numerele negative nu.

De ce avem 256 de valori, dar maximul este 255?

Un bit are două valori. Opt biți oferă 2⁸ = 256 combinații. Dacă numerotați de la zero, acestea reprezintă 0, 1, …, 255. Valoarea 256 ar avea nevoie de nouă poziții în binar: 100000000.

4 · Completați afișarea hexazecimală

În PROJECT/lab.js, căutați funcția toHex8. Vedeți apelul validateByte(u) și return null;. Validarea rămâne: modificați numai rezultatul din această funcție.

Un caracter hexazecimal descrie patru biți: 0000 este 0, 1010 este A, 1111 este F. Prin urmare, opt biți se grupează în două caractere. Pentru 5, 0000 0101 devine 05; zeroul inițial asigură reprezentarea pe două caractere. Pentru 255, 1111 1111 devine FF.

Folosiți operațiile de mai jos ca să construiți textul cerut:

4 · Completați afișarea hexazecimală
Operație JavaScriptRolExemplu
u.toString(16)Scrie numărul în baza 16 și întoarce text.255 → 'ff'.
.padStart(2, '0')Completează textul cu zero la stânga până la două caractere.'5' → '05'.
.toUpperCase()Transformă literele în majuscule.'ff' → 'FF'.

Puteți aplica operațiile succesiv sau puteți folosi variabile intermediare. return întoarce textul final. Salvați cu Ctrl+S/Cmd+S, reîncărcați fila aplicației și comparați 0, 5, 128 și 255.

Sprijin de sintaxă, după ce ați încercat

Înlocuiți numai return null; din toHex8 cu linia de mai jos. Ea merge în fișierul JavaScript, nu în terminal. Citiți fiecare operație și explicați de ce nu ajunge numai toString(16).

Unde se copiază: în funcția toHex8 din PROJECT/lab.js.

return u.toString(16).padStart(2, '0').toUpperCase();
Dacă schimbarea nu apare în aplicație

Verificați întâi salvarea, apoi adresa filei: trebuie să fie fișierul din copia clonată. Reîncărcați pagina. Dacă vedeți 5 în loc de 05, lipsește completarea lungimii; dacă vedeți ff, lipsește transformarea în majuscule. Pentru o eroare de sintaxă verificați punctele, ghilimelele, parantezele și punctul și virgula; consola browserului poate arăta linia problemei.

6 · Selectați, înregistrați și publicați modificarea

În VS Code, deschideți Source Control. În lista Changes, apăsați fiecare fișier modificat: vizualizarea diferențelor, numită diff, arată liniile vechi și noi. Puteți explica de ce apare fiecare schimbare?

  1. Apăsați + lângă fișierele relevante: lab.js, README.md, evidence.md și custom-tests.js dacă l-ați modificat. Ele apar în Staged Changes, adică au fost selectate pentru următorul commit.
  2. Scrieți un mesaj, de exemplu S05: afisare hexazecimala pe doua caractere, apoi alegeți Commit. Acum Git înregistrează local versiunea selectată.
  3. Alegeți Push din meniul Source Control și încheiați autentificarea, dacă este cerută. Această operație trimite commitul către origin.
  4. În browser reîncărcați depozitul dumneavoastră GitHub pe main. Verificați mesajul commitului și funcția toHex8.

Alternativă în terminal, după citirea diferențelor

Rulați din rădăcina depozitului. Dacă ați modificat și custom-tests.js, adăugați-l explicit la comanda git add. Comenzile nu înlocuiesc citirea diferențelor.

Unde se copiază: în terminalul VS Code, din rădăcina depozitului.

git status
git diff
git add PROJECT/lab.js PROJECT/README.md PROJECT/evidence.md
git diff --cached
git commit -m "S05: afisare hexazecimala pe doua caractere"
git push origin main
git status

git diff arată schimbările încă neselectate; git diff --cached arată conținutul pregătit pentru commit. O stare locală curată după commit nu dovedește singură că push-ul a reușit.

Dacă vă blocați la commit sau push
  • Author identity unknown: configurați identitatea locală din Pregătire, apoi repetați commitul.
  • Nothing to commit: verificați dacă ați salvat și selectat schimbarea sau ați făcut deja commit.
  • Repository not found / acces refuzat: verificați origin, contul autentificat și accesul la depozitul privat.
  • Push respins: păstrați mesajul și verificați situația înainte de sincronizare. Nu folosiți force push sau comenzi de ștergere ca să grăbiți publicarea.

7 · Verificați informațiile pentru reluare și rezolvați Q05

În minutele 70–75 verificați fișa de reluare și publicarea ei. Dacă o completați abia acum, salvați, faceți încă un commit și push. La S06 veți ști ce director să deschideți și de unde să reluați.

În minutele 75–85 deschideți Q05 în Moodle. Lucrați individual, fără Gemini, alt AI sau ajutorul colegilor; fișa comună de referință este permisă. Q05 are maximum 20 de puncte în Moodle, adică 0,20 puncte la punctajul de seminar. Testul verifică înțelegerea reprezentării și a stărilor Git. Acesta nu efectuează un audit automat al codului propriu.
