S05 · Preiei, verifici şi publici

Completezi reprezentarea hexazecimală şi verifici unde există prima ta schimbare.

Ce vei putea explica la final

Vei avea un repository propriu, o copie locală şi o primă modificare publicată: afişarea hexazecimală pe două caractere. Vei putea răspunde la întrebarea „Unde există acum schimbarea mea?” după salvare, commit şi push.

Urmăreşte paşii de mai jos în timpul activităţii. Secţiunile cu explicaţii te ajută dacă ai o nelămurire şi rămân disponibile după seminar.

1 · Creează repository-ul tău din template

Lucrezi în browser, pe GitHub. Deschide şablonul comun BBS-bit-byte-starter. Recunoaşte proiectul: în rădăcină trebuie să existe PROJECT, GUIDES şi START.html.

  1. Alege Use this template → Create a new repository.
  2. La Owner selectează contul tău. Poţi folosi un nume precum bti-byte-lab; dacă grupa are o regulă de denumire anunţată, urmeaz-o.
  3. Alege vizibilitatea indicată pentru grupă. Pentru un repository privat, linkul nu acordă automat drept de citire altcuiva.
  4. Creează copia numai din ramura implicită; nu cere includerea tuturor ramurilor.

După creare, antetul şi adresa paginii trebuie să arate CONTUL_TAU/REPOSITORY_UL_TAU. Vei publica aici, fără să modifici template-ul grupei. Repository-ul este proiectul cu istoricul său; template-ul oferă acelaşi punct de pornire tuturor.

Dacă lipseşte „Use this template”

Verifică dacă ai deschis linkul indicat, eşti conectat şi ai acces. Dacă repository-ul nu este marcat drept template, cadrul didactic trebuie să verifice pregătirea lui. Nu crea o copie goală ca înlocuitor şi nu publica schimbările în repository-ul comun.

2 · Clonează adresa copiei tale în VS Code

În repository-ul tău de pe GitHub, apasă Code → HTTPS şi copiază URL-ul care se termină cu .git. Acum treci în VS Code:

  1. Deschide Command Palette cu Ctrl+Shift+P pe Windows/Linux sau Cmd+Shift+P pe macOS.
  2. Alege Git: Clone, introdu URL-ul copiat şi selectează directorul părinte pregătit.
  3. La final alege Open pentru directorul clonat. Dacă apare întrebarea despre încredere, verifică întâi că este proiectul furnizat, în copia ta.
  4. Deschide Terminal → New Terminal în rădăcina proiectului şi verifică:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git status
git remote -v
git branch --show-current

Trebuie să vezi ramura main, nicio modificare locală şi adresa repository-ului tău la origin, pentru fetch şi push. origin este numele scurt pe care Git îl dă de obicei repository-ului de la care ai clonat. Dacă adresa indică template-ul, ai clonat sursa comună; deschide copia ta într-un director separat.

Configurează sau verifică identitatea autorului înainte de primul commit. Pe un cont partajat foloseşte numai configurarea locală a acestui repository. Identitatea autorului nu schimbă contul cu care te autentifici pentru push.

Ce primeşti prin clone, faţă de un ZIP

Clone descarcă fişierele, istoricul Git şi legătura origin. Un ZIP oferă fişiere pentru citire, fără să pregătească acest circuit. Pentru lucru deschide GUIDES/RO/S05.html din copia clonată, ca linkurile către aplicaţie să folosească acelaşi director.

Dacă git status spune „not a git repository”, ai deschis alt director. Foloseşte File → Open Folder şi alege directorul clonat, nu directorul părinte.

Alternativă: clonare din terminal

Foloseşte această variantă în locul comenzii Git: Clone. Terminalul trebuie deschis în directorul părinte. Înlocuieşte contul şi numele repository-ului; după comenzi deschide în VS Code directorul creat.

Unde se copiază: în terminalul VS Code, din directorul părinte ales pentru clonare.

git clone https://github.com/CONTUL_TAU/REPOSITORY_UL_TAU.git
cd REPOSITORY_UL_TAU
git status

3 · Fă o predicţie şi rulează proiectul

În VS Code, deschide PROJECT/evidence.md. La S05 notează ce aştepţi pentru 0, 5 şi 255: binarul pe opt poziţii şi hexazecimalul pe două. Scrie înainte să rulezi sau să întrebi Gemini, ca să ai cu ce compara observaţia.

Din managerul de fişiere al calculatorului deschide PROJECT/index.html cu browserul. Din VS Code poţi folosi opţiunea de afişare a fişierului în File Explorer/Finder, apoi îl deschizi. Introdu numărul zecimal în aplicaţie: rezultatele se actualizează automat, fără buton de rulare.

Binarul este deja implementat; hexazecimalul va indica neimplementat până îl completezi. Interpretarea cu semn are o problemă pregătită pentru S06, iar paritatea va fi completată în S07. Nu trebuie ca funcţiile viitoare să fie gata astăzi.

Deschide şi PROJECT/tests.html, selectează baseline şi apasă rularea. Aceste verificări privesc funcţiile deja furnizate şi trebuie să treacă înainte să editezi. Etapele S05–S07 includ cerinţe încă neîncheiate.

Introdu şi 256: trebuie respins. Câmpul primeşte întregi zecimali 0–255, nu 0xFF sau text binar. Spaţiile de la capete şi zerourile iniţiale sunt acceptate, iar golul, textul, fracţiile şi numerele negative nu.

De ce avem 256 de valori, dar maximul este 255?

Un bit are două valori. Opt biţi oferă 2⁸ = 256 combinaţii. Dacă numerotezi de la zero, acestea reprezintă 0, 1, …, 255. Valoarea 256 ar avea nevoie de nouă poziţii în binar: 100000000.

4 · Completează afişarea hexazecimală

În PROJECT/lab.js, caută funcţia toHex8. Vezi apelul validateByte(u) şi return null;. Validarea rămâne: modifici numai rezultatul din această funcţie.

Un caracter hexazecimal descrie patru biţi: 0000 este 0, 1010 este A, 1111 este F. Prin urmare, opt biţi se grupează în două caractere. Pentru 5, 0000 0101 devine 05; zero-ul din faţă păstrează dimensiunea octetului. Pentru 255, 1111 1111 devine FF.

Foloseşte operaţiile de mai jos ca să construieşti textul cerut:

4 · Completează afişarea hexazecimală
Operaţie JavaScriptRolExemplu
u.toString(16)Scrie numărul în baza 16 şi întoarce text.255 → 'ff'.
.padStart(2, '0')Completează textul cu zero la stânga până la două caractere.'5' → '05'.
.toUpperCase()Transformă literele în majuscule.'ff' → 'FF'.

Poţi aplica operaţiile succesiv sau poţi folosi variabile intermediare. return întoarce textul final. Salvează cu Ctrl+S/Cmd+S, reîncarcă tabul aplicaţiei şi compară 0, 5, 128 şi 255.

Sprijin de sintaxă, după ce ai încercat

Înlocuieşte numai return null; din toHex8 cu linia de mai jos. Ea merge în fişierul JavaScript, nu în terminal. Citeşte fiecare operaţie şi explică de ce nu ajunge numai toString(16).

Unde se copiază: în funcţia toHex8 din PROJECT/lab.js.

return u.toString(16).padStart(2, '0').toUpperCase();
Dacă schimbarea nu apare în aplicaţie

Verifică întâi salvarea, apoi adresa tabului: trebuie să fie fişierul din copia clonată. Reîncarcă pagina. Dacă vezi 5 în loc de 05, lipseşte completarea lungimii; dacă vezi ff, lipseşte transformarea în majuscule. Pentru o eroare de sintaxă verifică punctele, ghilimelele, parantezele şi punctul şi virgula; consola browserului poate arăta linia problemei.

6 · Selectează, înregistrează şi publică schimbarea

În VS Code, deschide Source Control. În lista Changes, apasă fiecare fişier modificat: vizualizarea diferenţelor, numită diff, arată liniile vechi şi noi. Poţi explica de ce apare fiecare schimbare?

  1. Apasă + lângă fişierele relevante: lab.js, README.md, evidence.md şi custom-tests.js dacă l-ai modificat. Ele apar în Staged Changes, adică au fost selectate pentru următorul commit.
  2. Scrie un mesaj, de exemplu S05: afisare hexazecimala pe doua caractere, apoi alege Commit. Acum Git înregistrează local versiunea selectată.
  3. Alege Push din meniul Source Control şi încheie autentificarea, dacă este cerută. Această operaţie trimite commitul către origin.
  4. În browser reîncarcă repository-ul tău GitHub pe main. Verifică mesajul commitului şi funcţia toHex8.

Alternativă în terminal, după citirea diferenţelor

Rulează din rădăcina repository-ului. Dacă ai modificat şi custom-tests.js, adaugă-l explicit la comanda git add. Comenzile nu înlocuiesc citirea diferenţelor.

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git status
git diff
git add PROJECT/lab.js PROJECT/README.md PROJECT/evidence.md
git diff --cached
git commit -m "S05: afisare hexazecimala pe doua caractere"
git push origin main
git status

git diff arată schimbările încă neselectate; git diff --cached arată conţinutul pregătit pentru commit. O stare locală curată după commit nu dovedeşte singură că push-ul a reuşit.

Dacă te blochezi la commit sau push
  • Author identity unknown: configurează identitatea locală din Pregătire, apoi repetă commitul.
  • Nothing to commit: verifică dacă ai salvat şi selectat schimbarea sau ai făcut deja commit.
  • Repository not found / acces refuzat: verifică origin, contul autentificat şi accesul la repository-ul privat.
  • Push respins: păstrează mesajul şi verifică situaţia înainte de sincronizare. Nu folosi force push sau comenzi de ştergere ca să grăbeşti publicarea.

7 · Confirmă reluarea şi rezolvă Q05

În minutele 70–75 verifică fişa de reluare şi publicarea ei. Dacă o completezi abia acum, salvează, fă încă un commit şi push. La S06 vei şti ce director să deschizi şi de unde să reiei.

În minutele 75–85 deschide Q05 în Moodle. Lucrezi individual, fără Gemini, alt AI sau ajutorul colegilor; fişa comună de referinţă este permisă. Q05 are maximum 20 de puncte interne, adică 0,20 puncte reale. Verifică înţelegerea reprezentării şi a stărilor Git, nu o auditare automată a codului tău.
