Ce vei putea explica la final

Vei avea un repository propriu, o copie locală și o primă modificare publicată: afișarea hexazecimală pe două caractere. Vei putea răspunde la întrebarea „Unde există acum schimbarea mea?” după salvare, commit și push.

Urmărește pașii de mai jos în timpul activității. Secțiunile cu explicații te ajută dacă ai o nelămurire și rămân disponibile după seminar.

Plan orientativ, încă neverificat cu grupele. Activitățile de mai jos includ quizul și încap în cele 90 de minute; indiciile se folosesc în etapa curentă.

1 · Creează repository-ul tău din template

Lucrezi în browser, pe GitHub. Deschide șablonul comun BBS-bit-byte-starter. Recunoaște proiectul: în rădăcină trebuie să existe PROJECT, GUIDES și START.html.

  1. Alege Use this template → Create a new repository.
  2. La Owner selectează contul tău. Poți folosi un nume precum bti-byte-lab; dacă grupa are o regulă de denumire anunțată, urmeaz-o.
  3. Alege vizibilitatea indicată pentru grupă. Pentru un repository privat, linkul nu acordă automat drept de citire altcuiva.
  4. Creează copia numai din ramura implicită; nu cere includerea tuturor ramurilor.

După creare, antetul și adresa paginii trebuie să arate CONTUL_TAU/REPOSITORY_UL_TAU. Vei publica aici, fără să modifici template-ul grupei. Repository-ul este proiectul cu istoricul său; template-ul oferă același punct de pornire tuturor.

Dacă lipsește „Use this template”

Verifică dacă ai deschis linkul indicat, ești conectat și ai acces. Dacă repository-ul nu este marcat drept template, cadrul didactic trebuie să verifice pregătirea lui. Nu crea o copie goală ca înlocuitor și nu publica schimbările în repository-ul comun.

2 · Clonează adresa copiei tale în VS Code

În repository-ul tău de pe GitHub, apasă Code → HTTPS și copiază URL-ul care se termină cu .git. Acum treci în VS Code:

  1. Deschide Command Palette cu Ctrl+Shift+P pe Windows/Linux sau Cmd+Shift+P pe macOS.
  2. Alege Git: Clone, introdu URL-ul copiat și selectează directorul părinte pregătit.
  3. La final alege Open pentru directorul clonat. Dacă apare întrebarea despre încredere, verifică întâi că este proiectul furnizat, în copia ta.
  4. Deschide Terminal → New Terminal în rădăcina proiectului și verifică:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git status
git remote -v
git branch --show-current

Trebuie să vezi ramura main, nicio modificare locală și adresa repository-ului tău la origin, pentru fetch și push. origin este numele scurt pe care Git îl dă de obicei repository-ului de la care ai clonat. Dacă adresa indică template-ul, ai clonat sursa comună; deschide copia ta într-un director separat.

Configurează sau verifică identitatea autorului înainte de primul commit. Pe un cont partajat folosește numai configurarea locală a acestui repository. Identitatea autorului nu schimbă contul cu care te autentifici pentru push.

Ce primești prin clone, față de un ZIP

Clone descarcă fișierele, istoricul Git și legătura origin. Un ZIP oferă fișiere pentru citire, fără să pregătească acest circuit. Pentru lucru deschide GUIDES/RO/S05.html din copia clonată, ca linkurile către aplicație să folosească același director.

Dacă git status spune „not a git repository”, ai deschis alt director. Folosește File → Open Folder și alege directorul clonat, nu directorul părinte.

Alternativă: clonare din terminal

Folosește această variantă în locul comenzii Git: Clone. Terminalul trebuie deschis în directorul părinte. Înlocuiește contul și numele repository-ului; după comenzi deschide în VS Code directorul creat.

Unde se copiază: în terminalul VS Code, din directorul părinte ales pentru clonare.

git clone https://github.com/CONTUL_TAU/REPOSITORY_UL_TAU.git
cd REPOSITORY_UL_TAU
git status

3 · Fă o predicție și rulează proiectul

În VS Code, deschide PROJECT/evidence.md. La S05 notează ce aștepți pentru 0, 5 și 255: binarul pe opt poziții și hexazecimalul pe două. Scrie înainte să rulezi sau să întrebi Gemini, ca să ai cu ce compara observația.

Din managerul de fișiere al calculatorului deschide PROJECT/index.html cu browserul. Din VS Code poți folosi opțiunea de afișare a fișierului în File Explorer/Finder, apoi îl deschizi. Introdu numărul zecimal în aplicație: rezultatele se actualizează automat, fără buton de rulare.

Binarul este deja implementat; hexazecimalul va indica neimplementat până îl completezi. Interpretarea cu semn are o problemă pregătită pentru S06, iar paritatea va fi completată în S07. Nu trebuie ca funcțiile viitoare să fie gata astăzi.

Deschide și PROJECT/tests.html, selectează baseline și apasă rularea. Aceste verificări privesc funcțiile deja furnizate și trebuie să treacă înainte să editezi. Etapele S05–S07 includ cerințe încă neîncheiate.

Introdu și 256: trebuie respins. Câmpul primește întregi zecimali 0–255, nu 0xFF sau text binar. Spațiile de la capete și zerourile inițiale sunt acceptate, iar golul, textul, fracțiile și numerele negative nu.

De ce avem 256 de valori, dar maximul este 255?

Un bit are două valori. Opt biți oferă 2⁸ = 256 combinații. Dacă numerotezi de la zero, acestea reprezintă 0, 1, …, 255. Valoarea 256 ar avea nevoie de nouă poziții în binar: 100000000.

4 · Completează afișarea hexazecimală

În PROJECT/lab.js, caută funcția toHex8. Vezi apelul validateByte(u) și return null;. Validarea rămâne: modifici numai rezultatul din această funcție.

Un caracter hexazecimal descrie patru biți: 0000 este 0, 1010 este A, 1111 este F. Prin urmare, opt biți se grupează în două caractere. Pentru 5, 0000 0101 devine 05; zero-ul din față păstrează dimensiunea octetului. Pentru 255, 1111 1111 devine FF.

Folosește operațiile de mai jos ca să construiești textul cerut:

4 · Completează afișarea hexazecimală
Operație JavaScriptRolExemplu
u.toString(16)Scrie numărul în baza 16 și întoarce text.255 → 'ff'.
.padStart(2, '0')Completează textul cu zero la stânga până la două caractere.'5' → '05'.
.toUpperCase()Transformă literele în majuscule.'ff' → 'FF'.

Poți aplica operațiile succesiv sau poți folosi variabile intermediare. return întoarce textul final. Salvează cu Ctrl+S/Cmd+S, reîncarcă tabul aplicației și compară 0, 5, 128 și 255.

Sprijin de sintaxă, după ce ai încercat

Înlocuiește numai return null; din toHex8 cu linia de mai jos. Ea merge în fișierul JavaScript, nu în terminal. Citește fiecare operație și explică de ce nu ajunge numai toString(16).

Unde se copiază: în funcția toHex8 din PROJECT/lab.js.

return u.toString(16).padStart(2, '0').toUpperCase();
Dacă schimbarea nu apare în aplicație

Verifică întâi salvarea, apoi adresa tabului: trebuie să fie fișierul din copia clonată. Reîncarcă pagina. Dacă vezi 5 în loc de 05, lipsește completarea lungimii; dacă vezi ff, lipsește transformarea în majuscule. Pentru o eroare de sintaxă verifică punctele, ghilimelele, parantezele și punctul și virgula; consola browserului poate arăta linia problemei.

6 · Selectează, înregistrează și publică schimbarea

În VS Code, deschide Source Control. În lista Changes, apasă fiecare fișier modificat: vizualizarea diferențelor, numită diff, arată liniile vechi și noi. Poți explica de ce apare fiecare schimbare?

  1. Apasă + lângă fișierele relevante: lab.js, README.md, evidence.md și custom-tests.js dacă l-ai modificat. Ele apar în Staged Changes, adică au fost selectate pentru următorul commit.
  2. Scrie un mesaj, de exemplu S05: afisare hexazecimala pe doua caractere, apoi alege Commit. Acum Git înregistrează local versiunea selectată.
  3. Alege Push din meniul Source Control și încheie autentificarea, dacă este cerută. Această operație trimite commitul către origin.
  4. În browser reîncarcă repository-ul tău GitHub pe main. Verifică mesajul commitului și funcția toHex8.

Alternativă în terminal, după citirea diferențelor

Rulează din rădăcina repository-ului. Dacă ai modificat și custom-tests.js, adaugă-l explicit la comanda git add. Comenzile nu înlocuiesc citirea diferențelor.

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git status
git diff
git add PROJECT/lab.js PROJECT/README.md PROJECT/evidence.md
git diff --cached
git commit -m "S05: afisare hexazecimala pe doua caractere"
git push origin main
git status

git diff arată schimbările încă neselectate; git diff --cached arată conținutul pregătit pentru commit. O stare locală curată după commit nu dovedește singură că push-ul a reușit.

Dacă te blochezi la commit sau push
  • Author identity unknown: configurează identitatea locală din Pregătire, apoi repetă commitul.
  • Nothing to commit: verifică dacă ai salvat și selectat schimbarea sau ai făcut deja commit.
  • Repository not found / acces refuzat: verifică origin, contul autentificat și accesul la repository-ul privat.
  • Push respins: păstrează mesajul și verifică situația înainte de sincronizare. Nu folosi force push sau comenzi de ștergere ca să grăbești publicarea.

7 · Confirmă reluarea și rezolvă Q05

În minutele 70–75 verifică fișa de reluare și publicarea ei. Dacă o completezi abia acum, salvează, fă încă un commit și push. La S06 vei ști ce director să deschizi și de unde să reiei.
