2 · Înţelege cerinţa şi prezice bitul de control

Varianta atribuită în seminar este A — even, paritate pară sau B — odd, paritate impară. Implementezi numai modul atribuit. În README vei spune ce mod este completat şi ce mod rămâne neimplementat.

Numără biţii 1 din cei opt biţi de date: numim acest număr k. Adaugi un bit p la dreapta, astfel încât totalul k + p să fie par pentru A sau impar pentru B. Dacă totalul are deja paritatea cerută, adaugi 0; dacă trebuie schimbată, adaugi 1.

2 · Înţelege cerinţa şi prezice bitul de control
DatekA: p pentru total parB: p pentru total impar
3 = 0000001120: total 2.1: total 3.
7 = 0000011131: total 4.0: total 3.

În PROJECT/evidence.md, înainte de implementare, notează pentru varianta ta rezultatele aşteptate la 3 şi 7. Notează şi că 256 trebuie respins, fiind în afara intervalului unui octet.

Opt biţi de date + un bit separat de paritate = un cuvânt de nouă biţi. Nu ai făcut un octet de nouă biţi şi nu ai schimbat interpretarea cu semn. Pentru A şi 3, rezultatul transmis este 000000110; ultimul 0 este bitul de control.
Cum scrii regula prin restul împărţirii?

În JavaScript, k % 2 este restul împărţirii la 2: 0 dacă k este par şi 1 dacă k este impar. Pentru A, p = k % 2. Pentru B, p = 1 − (k % 2). Rezultatul trebuie să fie numărul 0 sau 1, nu text şi nu valoarea totală k + p.

Cu paritatea încă necompletată, cazurile 3 şi 7 apar ca Neimplementat, nu ca rezultat corect. Testul pentru 256 trebuie să treacă deja: validarea este furnizată. Notează starea iniţială, apoi revino aici şi implementează. Nu schimba aşteptările ca să se potrivească unui rezultat greşit.

În PROJECT/lab.js găseşte parityBit8(u, mode). Validarea şi două blocuri există deja: if (mode === 'even') şi if (mode === 'odd'). Înlocuieşti return null; numai în blocul variantei tale.

Funcţia auxiliară countOnes8(u) este furnizată şi întoarce k. Poţi folosi const k = countOnes8(u);, apoi un return cu regula aleasă. Verifică pe hârtie ce întoarce expresia pentru k = 2 şi k = 3 înainte să rulezi.

Citeşte operaţia fiecărei linii şi nu şterge testele. Foloseşte numai setul variantei atribuite; celălalt mod poate rămâne neimplementat.

Dacă un test eşuează
  • Neimplementat: verifică modul selectat şi blocul editat.
  • Rezultatele sunt mereu inverse: verifică diferenţa dintre paritate pară şi impară.
  • Tip de rezultat greşit: funcţia întoarce un număr 0 sau 1, nu textul '0' sau '1'.
  • Testele proprii nu apar: verifică virgulele dintre obiecte, salvarea şi reîncărcarea.
  • S05/S06 eşuează: citeşte diff-ul pentru schimbări accidentale în alte funcţii.
Ce erori poate detecta paritatea?

Pentru A, datele 3 dau 000000110, cu doi biţi 1. Dacă un 0 din date devine 1, totalul devine trei şi verificarea semnalează eroarea. Dacă doi biţi 0 devin 1, totalul devine patru şi rămâne par; eroarea trece această verificare.

O schimbare de bit, inclusiv a bitului de control, schimbă paritatea. Orice număr impar de schimbări este detectat; un număr par o poate păstra. Paritatea simplă nu localizează bitul greşit şi nu corectează datele.

6 · Verifică versiunea publicată dintr-o clonare nouă

Copia în care ai lucrat poate conţine fişiere neincluse în commit. Clonează din nou pentru a verifica fişierele şi versiunea care se află efectiv pe GitHub.

  1. Copiază URL-ul HTTPS al repository-ului tău.
  2. În VS Code alege Git: Clone, apoi alt director părinte, de exemplu Documents/BTI_REPRO. Nu clona în interiorul proiectului original sau peste copia existentă.
  3. Deschide directorul nou într-o altă fereastră. Numele repository-ului poate fi acelaşi; verifică calea diferită.
  4. În terminalul copiei noi rulează verificările:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git branch --show-current
git status
git rev-parse HEAD

Trebuie să vezi repository-ul propriu, main, stare curată şi acelaşi SHA complet ca după publicarea finală. Acum deschide aplicaţia şi testele din PROJECT al copiei noi. Verifică adresa tabului browserului: un tab vechi ar putea rula încă proiectul original.
