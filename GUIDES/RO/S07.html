2 · Înțelege cerința și prezice bitul de control

Varianta atribuită în seminar este A — even, paritate pară sau B — odd, paritate impară. Implementezi numai modul atribuit. În README vei spune ce mod este completat și ce mod rămâne neimplementat.

Numără biții 1 din cei opt biți de date: numim acest număr k. Adaugi un bit p la dreapta, astfel încât totalul k + p să fie par pentru A sau impar pentru B. Dacă totalul are deja paritatea cerută, adaugi 0; dacă trebuie schimbată, adaugi 1.

2 · Înțelege cerința și prezice bitul de control
DatekA: p pentru total parB: p pentru total impar
3 = 0000001120: total 2.1: total 3.
7 = 0000011131: total 4.0: total 3.

În PROJECT/evidence.md, înainte de implementare, notează pentru varianta ta rezultatele așteptate la 3 și 7. Notează și că 256 trebuie respins, fiind în afara intervalului unui octet.

Opt biți de date + un bit separat de paritate = un cuvânt de nouă biți. Nu ai făcut un octet de nouă biți și nu ai schimbat interpretarea cu semn. Pentru A și 3, rezultatul transmis este 000000110; ultimul 0 este bitul de control.
Cum scrii regula prin restul împărțirii?

În JavaScript, k % 2 este restul împărțirii la 2: 0 dacă k este par și 1 dacă k este impar. Pentru A, p = k % 2. Pentru B, p = 1 − (k % 2). Rezultatul trebuie să fie numărul 0 sau 1, nu text și nu valoarea totală k + p.

3 · Observă starea inițială, apoi completează modul atribuit

Înainte să modifici funcția: păstrează predicțiile pentru 3 și 7 și adaugă cele trei teste proprii folosind blocul variantei tale de la pasul 4. Păstrează testele existente, inclusiv cel pentru 128 din S06. Salvează, reîncarcă PROJECT/tests.html, selectează S07 și varianta atribuită și rulează.

Cu paritatea încă necompletată, cazurile 3 și 7 apar ca Neimplementat, nu ca rezultat corect. Testul pentru 256 trebuie să treacă deja: validarea este furnizată. Notează starea inițială, apoi revino aici și implementează. Nu schimba așteptările ca să se potrivească unui rezultat greșit.

În PROJECT/lab.js găsește parityBit8(u, mode). Validarea și două blocuri există deja: if (mode === 'even') și if (mode === 'odd'). Înlocuiești return null; numai în blocul variantei tale.

Funcția auxiliară countOnes8(u) este furnizată și întoarce k. Poți folosi const k = countOnes8(u);, apoi un return cu regula aleasă. Verifică pe hârtie ce întoarce expresia pentru k = 2 și k = 3 înainte să rulezi.

Testele proprii rulează și când alegi S05 sau S06. Înainte de implementarea parității, aceste etape pot afișa testele proprii 3 și 7 ca neimplementate, deși verificările lor anterioare sunt corecte. Citește operația fiecărei linii și nu șterge testele. Folosește numai setul variantei atribuite; celălalt mod poate rămâne neimplementat.

Dacă un test eșuează
  • Neimplementat: verifică modul selectat și blocul editat.
  • Rezultatele sunt mereu inverse: verifică diferența dintre paritate pară și impară.
  • Tip de rezultat greșit: funcția întoarce un număr 0 sau 1, nu textul '0' sau '1'.
  • Testele proprii nu apar: verifică virgulele dintre obiecte, salvarea și reîncărcarea.
  • S05/S06 eșuează: citește diff-ul pentru schimbări accidentale în alte funcții.
Ce erori poate detecta paritatea?

Pentru A, datele 3 dau 000000110, cu doi biți 1. Dacă un 0 din date devine 1, totalul devine trei și verificarea semnalează eroarea. Dacă doi biți 0 devin 1, totalul devine patru și rămâne par; eroarea trece această verificare.

O schimbare de bit, inclusiv a bitului de control, schimbă paritatea. Orice număr impar de schimbări este detectat; un număr par o poate păstra. Paritatea simplă nu localizează bitul greșit și nu corectează datele.

6 · Verifică versiunea publicată dintr-o clonare nouă

Copia în care ai lucrat poate conține fișiere neincluse în commit. Clonează din nou pentru a verifica fișierele și versiunea care se află efectiv pe GitHub.

  1. Copiază URL-ul HTTPS al repository-ului tău.
  2. În VS Code alege Git: Clone, apoi alt director părinte, de exemplu Documents/BTI_REPRO. Nu clona în interiorul proiectului original sau peste copia existentă.
  3. Deschide directorul nou într-o altă fereastră. Numele repository-ului poate fi același; verifică calea diferită.
  4. În terminalul copiei noi rulează verificările:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git branch --show-current
git status

Trebuie să vezi repository-ul propriu, main, stare curată și același SHA complet ca după publicarea finală. Acum deschide aplicația și testele din PROJECT al copiei noi. Verifică adresa tabului browserului: un tab vechi ar putea rula încă proiectul original.
