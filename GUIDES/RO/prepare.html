Înainte de S05

Verifici instrumentele şi conturile o singură dată, ca să poţi lucra în proiect la seminar.

Ce verifici înainte de seminar

Ai nevoie de contul tău GitHub, Git, VS Code, un browser şi acces la cursul BTI din Moodle. Git păstrează versiunile pe calculator; GitHub este serviciul online. Instalarea VS Code nu înlocuieşte instalarea Git.

Pe calculatorul de laborator foloseşte configuraţia pregătită de instituţie. Dacă lipseşte un instrument sau instalarea cere drepturi de administrator, semnalează din timp. Pe calculatorul personal foloseşte pagina oficială VS Code şi pagina oficială Git, alegând sistemul tău de operare.

Aplicaţia acestui proiect se deschide direct din fişierul HTML. Nu trebuie să instalezi Node.js, Python, Live Server sau un server web. GitHub, Moodle şi Gemini au nevoie de internet; aplicaţia şi testele locale nu.

1 · Verifică instalarea Git în VS Code

Deschide VS Code, apoi Terminal → New Terminal. Terminalul este zona în care scrii comenzi pentru calculator; nu este un fişier JavaScript. Rulează:

Unde se copiază: în terminalul VS Code.

git --version

Trebuie să apară git version urmat de numărul versiunii. Comanda doar verifică instalarea; nu creează un repository şi nu se conectează la GitHub.

SistemLa ce să fii atent
WindowsInstalează Git for Windows prin pagina oficială. Git trebuie să fie disponibil din linia de comandă şi pentru alte aplicaţii. Redeschide VS Code după instalare. PowerShell poate fi folosit pentru comenzile din ghid.
macOSFoloseşte metoda indicată pe pagina oficială Git pentru macOS sau configuraţia instituţiei. Dacă sistemul cere instalarea Command Line Tools, încheie instalarea permisă înainte de verificare.
LinuxUrmează instrucţiunile pentru distribuţia ta de pe pagina oficială. Pe un calculator administrat, instalarea este responsabilitatea persoanei care îl gestionează.
Dacă apare „git nu este recunoscut” sau „command not found”

Închide şi redeschide VS Code, apoi repetă verificarea. Dacă mesajul rămâne, Git lipseşte sau nu este disponibil aplicaţiei. Repară instalarea prin metoda oficială ori anunţă problema pe calculatorul de laborator. Nu copia manual executabile în directorul proiectului.

2 · Verifică accesul în conturile potrivite

  1. Deschide GitHub în browser. În meniul contului verifică numele utilizatorului: trebuie să fie contul tău.
  2. Deschide online.ase.ro şi găseşte cursul BTI al grupei. Acolo vei primi linkul către repository-ul de pornire şi activităţile de evaluare.
  3. Opţional, verifică accesul la Gemini. Dacă nu este disponibil, ştii unde găseşti alternativa pregătită.

La clone sau push, VS Code poate cere separat autentificarea GitHub. Urmează conectarea interactivă şi verifică în browser ce cont autorizezi. O pagină GitHub deschisă în browser nu dovedeşte singură că Git va publica folosind acelaşi cont.

Calculator folosit de mai mulţi studenţi

Un cont comun al sistemului de operare poate păstra autorizări din VS Code sau din gestionarul de credenţiale Git. Configurarea numelui autorului, descrisă mai jos, nu schimbă aceste autorizări. Dacă apare un cont străin, opreşte conectarea şi urmează procedura laboratorului pentru o sesiune proprie. Deconectarea din browser poate fi insuficientă pentru autorizările păstrate de celelalte aplicaţii.

La plecare încheie sesiunea conform aceleiaşi proceduri. Nu şterge în grabă toate credenţialele calculatorului sau proiectele altora; problema trebuie rezolvată prin configuraţia pregătită pentru laborator.

Parolele, codurile de recuperare şi tokenurile nu se introduc în cod, în prompturi sau în tema Moodle. Ghidul foloseşte autentificarea interactivă obişnuită, fără comenzi care conţin secrete.

3 · Alege identitatea autorului

Fiecare commit înregistrează un nume şi un email de autor. Acestea sunt etichete ale versiunii, nu autentificarea GitHub. Alege-le înainte de primul commit. Pentru un email privat, deschide în GitHub Settings → Emails şi copiază exact adresa noreply furnizată contului; nu o construi din memorie.

Varianta recomandată în laborator: configurare numai pentru repository-ul tău

La S05 vei clona proiectul. Abia atunci, din terminalul acelui repository, înlocuieşti textele dintre ghilimele şi rulezi:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git config user.name "Numele ales"
git config user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --get user.name
git config --get user.email

Ultimele două comenzi trebuie să arate valorile alese de tine. Primele două nu afişează de obicei nimic când reuşesc. Fără --global, configuraţia se aplică numai repository-ului curent. Această variantă este potrivită şi pe calculatorul personal.

Opţional: configurare globală pe un cont personal al sistemului de operare

Foloseşte această variantă numai dacă eşti singurul utilizator al contului din sistemul de operare. Ea se aplică repository-urilor acelui utilizator, dacă nu au o configurare locală care o înlocuieşte. Înlocuieşte exemplele:

Unde se copiază: în terminalul VS Code.

git config --global user.name "Numele ales"
git config --global user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --global --get user.name
git config --global --get user.email

Pe un cont de laborator comun nu folosi --global: ai schimba identitatea implicită şi pentru ceilalţi utilizatori.

4 · Alege un loc pentru copia locală

Creează un director părinte uşor de regăsit, de exemplu Documents/BTI. La clonare îl vei selecta, iar Git va crea în el directorul proiectului. Nu alege o locaţie temporară care se şterge la ieşirea din cont.

Nu iniţializa acum un repository gol şi nu clona peste un director deja folosit. La S05 vei crea pe GitHub propria copie din template-ul indicat şi vei clona adresa copiei tale. Template-ul este repository-ul de pornire al grupei; copia ta va păstra schimbările tale.

Cum deosebeşti directorul părinte de directorul proiectului

Dacă ai ales Documents/BTI şi repository-ul se numeşte bti-byte-lab-xx, copia va fi în Documents/BTI/bti-byte-lab-xx. În VS Code vei deschide acest ultim director, cel care conţine PROJECT, GUIDES şi START.html. Deschiderea directorului părinte poate ascunde sau încurca starea Git a proiectului.

Poţi începe S05?

La începutul seminarului deschide S05. Aceasta este pregătirea instrumentelor, fără temă suplimentară de programare. Linkul real al template-ului trebuie să fie furnizat în Moodle înainte să poţi crea copia.
