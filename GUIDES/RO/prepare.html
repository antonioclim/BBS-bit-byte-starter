Înainte de S05

Pregătiți instrumentele și verificați conturile înaintea seminarului, pentru a putea începe lucrul în proiect.

Ce verificați înainte de seminar

Aveți nevoie de propriul cont GitHub, Git, VS Code, un browser și acces la cursul BTI din Moodle. Git păstrează versiunile pe calculator; GitHub este serviciul online. Instalarea VS Code nu înlocuiește instalarea Git.

Pe calculatorul de laborator folosiți configurația pregătită de instituție. Dacă lipsește un instrument sau instalarea necesită drepturi de administrator, semnalați din timp. Pe calculatorul personal folosiți pagina oficială VS Code și pagina oficială Git, alegând sistemul dumneavoastră de operare.

Aplicația proiectului se deschide direct din fișierul HTML. Nu sunt necesare Node.js, Python, Live Server sau un server web. GitHub, Moodle și Gemini necesită conexiune la internet; aplicația și testele se pot executa local fără această conexiune.

1 · Verificați instalarea Git în VS Code

Deschideți VS Code, apoi Terminal → New Terminal. Terminalul este interfața în care introduceți comenzi pentru calculator, separat de fișierele JavaScript ale proiectului. Rulați:

Unde se copiază: în terminalul VS Code.

git --version

Trebuie să apară git version urmat de numărul versiunii. Comanda verifică numai instalarea; nu creează un repository și nu se conectează la GitHub.

1 · Verificați instalarea Git în VS Code
SistemCe trebuie verificat
WindowsInstalați Git for Windows prin pagina oficială. Git trebuie să fie disponibil din linia de comandă și pentru alte aplicații. Redeschideți VS Code după instalare. PowerShell poate fi folosit pentru comenzile din ghid.
macOSFolosiți metoda indicată pe pagina oficială Git pentru macOS sau configurația instituției. Dacă sistemul solicită instalarea Command Line Tools, încheiați instalarea permisă înainte de verificare.
LinuxUrmați instrucțiunile pentru distribuția dumneavoastră de pe pagina oficială. Pe un calculator administrat, instalarea este responsabilitatea persoanei care îl gestionează.
Dacă apare „git nu este recunoscut” sau „command not found”

Închideți și redeschideți VS Code, apoi repetați verificarea. Dacă mesajul rămâne, Git lipsește sau nu este disponibil aplicației. Remediați instalarea prin metoda oficială ori anunțați problema pe calculatorul de laborator. Nu copiați manual fișiere executabile în directorul proiectului.

2 · Verificați accesul în conturile potrivite

  1. Deschideți GitHub în browser. În meniul contului verificați numele utilizatorului: trebuie să fie propriul cont.
  2. Deschideți online.ase.ro și identificați cursul BTI al grupei. Acolo găsiți activitățile de evaluare. Sursa proiectului este BBS-bit-byte-starter; în S05 veți crea din ea propriul repository.
  3. Opțional, verificați accesul la Gemini. Dacă nu este disponibil, știți unde găsiți alternativa pregătită.

La clonare sau la executarea operației push, VS Code poate solicita separat autentificarea GitHub. Urmați conectarea interactivă și verificați în browser ce cont autorizați. O pagină GitHub deschisă în browser nu dovedește singură că Git va publica folosind același cont.

Calculator folosit de mai mulți studenți

Un cont partajat al sistemului de operare poate păstra autorizări în VS Code sau în gestionarul datelor de autentificare Git (credential manager). Configurarea autorului, descrisă mai jos, nu modifică aceste autorizări. Dacă apare un cont străin, opriți conectarea și urmați procedura laboratorului pentru o sesiune proprie. Deconectarea din browser poate fi insuficientă pentru autorizările păstrate de celelalte aplicații.

La plecare încheiați sesiunea conform aceleiași proceduri. Nu ștergeți datele de autentificare ale altor utilizatori sau proiectele acestora; urmați configurația și procedura stabilite pentru laborator.

Parolele, codurile de recuperare și tokenurile nu se introduc în cod, în solicitările adresate instrumentelor AI (prompts) sau în tema Moodle. Ghidul folosește autentificarea interactivă obișnuită, fără comenzi care conțin secrete.

3 · Alegeți identitatea autorului

Fiecare commit înregistrează un nume și o adresă de e-mail a autorului. Aceste date identifică autorul versiunii, dar nu asigură autentificarea pe GitHub. Alegeți-le înainte de primul commit. Pentru o adresă de e-mail privată, deschideți în GitHub Settings → Emails și copiați exact adresa noreply furnizată contului; nu o reconstruiți din memorie.

Varianta recomandată în laborator: configurare numai pentru propriul repository

La S05 veți clona proiectul. Abia atunci, din terminalul acelui repository, înlocuiți textele dintre ghilimele și rulați:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git config user.name "Numele ales"
git config user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --get user.name
git config --get user.email

Ultimele două comenzi trebuie să arate valorile alese de dumneavoastră. Primele două nu afișează de obicei nimic când reușesc. Fără --global, configurația se aplică numai repository-ului curent. Această variantă este potrivită și pe calculatorul personal.

Opțional: configurare globală pe un cont personal al sistemului de operare

Folosiți această variantă numai dacă sunteți singurul utilizator al contului din sistemul de operare. Ea se aplică repository-urilor acelui utilizator, dacă nu au o configurare locală care o înlocuiește. Înlocuiți exemplele:

Unde se copiază: în terminalul VS Code.

git config --global user.name "Numele ales"
git config --global user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --global --get user.name
git config --global --get user.email

Pe un cont de laborator partajat nu folosiți --global: această configurare ar schimba identitatea implicită și pentru ceilalți utilizatori.

4 · Alegeți un loc pentru copia locală

Creați un director părinte ușor de regăsit, de exemplu Documents/BTI. La clonare îl veți selecta, iar Git va crea în el directorul proiectului. Nu alegeți o locație temporară care se șterge la ieșirea din cont.

Nu inițializați acum un repository gol și nu clonați peste un director deja folosit. La S05 veți crea pe GitHub propria copie din template-ul indicat și veți clona adresa copiei proprii. Șablonul (template repository) este proiectul de pornire al grupei; propriul repository va păstra modificările dumneavoastră.

Cum distingeți directorul părinte de directorul proiectului

Dacă ați ales Documents/BTI și repository-ul se numește bti-byte-lab-xx, copia va fi în Documents/BTI/bti-byte-lab-xx. În VS Code veți deschide acest ultim director, cel care conține PROJECT, GUIDES și START.html. Deschiderea directorului părinte poate îngreuna identificarea repository-ului și interpretarea stării Git.

Sunteți pregătiți pentru S05?

La începutul seminarului deschideți S05. Aceasta este pregătirea instrumentelor, fără temă suplimentară de programare. La S05 folosiți șablonul comun publicat, creați copia în propriul cont și clonați adresa ei.
