Înainte de S05

Verifici instrumentele și conturile o singură dată, ca să poți lucra în proiect la seminar.

Ce verifici înainte de seminar

Ai nevoie de contul tău GitHub, Git, VS Code, un browser și acces la cursul BTI din Moodle. Git păstrează versiunile pe calculator; GitHub este serviciul online. Instalarea VS Code nu înlocuiește instalarea Git.

Pe calculatorul de laborator folosește configurația pregătită de instituție. Dacă lipsește un instrument sau instalarea cere drepturi de administrator, semnalează din timp. Pe calculatorul personal folosește pagina oficială VS Code și pagina oficială Git, alegând sistemul tău de operare.

Aplicația acestui proiect se deschide direct din fișierul HTML. Nu trebuie să instalezi Node.js, Python, Live Server sau un server web. GitHub, Moodle și Gemini au nevoie de internet; aplicația și testele locale nu.

1 · Verifică instalarea Git în VS Code

Deschide VS Code, apoi Terminal → New Terminal. Terminalul este zona în care scrii comenzi pentru calculator; nu este un fișier JavaScript. Rulează:

Unde se copiază: în terminalul VS Code.

git --version

Trebuie să apară git version urmat de numărul versiunii. Comanda doar verifică instalarea; nu creează un repository și nu se conectează la GitHub.

1 · Verifică instalarea Git în VS Code
SistemLa ce să fii atent
WindowsInstalează Git for Windows prin pagina oficială. Git trebuie să fie disponibil din linia de comandă și pentru alte aplicații. Redeschide VS Code după instalare. PowerShell poate fi folosit pentru comenzile din ghid.
macOSFolosește metoda indicată pe pagina oficială Git pentru macOS sau configurația instituției. Dacă sistemul cere instalarea Command Line Tools, încheie instalarea permisă înainte de verificare.
LinuxUrmează instrucțiunile pentru distribuția ta de pe pagina oficială. Pe un calculator administrat, instalarea este responsabilitatea persoanei care îl gestionează.
Dacă apare „git nu este recunoscut” sau „command not found”

Închide și redeschide VS Code, apoi repetă verificarea. Dacă mesajul rămâne, Git lipsește sau nu este disponibil aplicației. Repară instalarea prin metoda oficială ori anunță problema pe calculatorul de laborator. Nu copia manual executabile în directorul proiectului.

2 · Verifică accesul în conturile potrivite

  1. Deschide GitHub în browser. În meniul contului verifică numele utilizatorului: trebuie să fie contul tău.
  2. Deschide online.ase.ro și găsește cursul BTI al grupei. Acolo găsești activitățile de evaluare. Sursa proiectului este BBS-bit-byte-starter; în S05 vei crea din ea repository-ul tău.
  3. Opțional, verifică accesul la Gemini. Dacă nu este disponibil, știi unde găsești alternativa pregătită.

La clone sau push, VS Code poate cere separat autentificarea GitHub. Urmează conectarea interactivă și verifică în browser ce cont autorizezi. O pagină GitHub deschisă în browser nu dovedește singură că Git va publica folosind același cont.

Calculator folosit de mai mulți studenți

Un cont comun al sistemului de operare poate păstra autorizări din VS Code sau din gestionarul de credențiale Git. Configurarea numelui autorului, descrisă mai jos, nu schimbă aceste autorizări. Dacă apare un cont străin, oprește conectarea și urmează procedura laboratorului pentru o sesiune proprie. Deconectarea din browser poate fi insuficientă pentru autorizările păstrate de celelalte aplicații.

La plecare încheie sesiunea conform aceleiași proceduri. Nu șterge în grabă toate credențialele calculatorului sau proiectele altora; problema trebuie rezolvată prin configurația pregătită pentru laborator.

Parolele, codurile de recuperare și tokenurile nu se introduc în cod, în prompturi sau în tema Moodle. Ghidul folosește autentificarea interactivă obișnuită, fără comenzi care conțin secrete.

3 · Alege identitatea autorului

Fiecare commit înregistrează un nume și un email de autor. Acestea sunt etichete ale versiunii, nu autentificarea GitHub. Alege-le înainte de primul commit. Pentru un email privat, deschide în GitHub Settings → Emails și copiază exact adresa noreply furnizată contului; nu o construi din memorie.

Varianta recomandată în laborator: configurare numai pentru repository-ul tău

La S05 vei clona proiectul. Abia atunci, din terminalul acelui repository, înlocuiești textele dintre ghilimele și rulezi:

Unde se copiază: în terminalul VS Code, din rădăcina repository-ului.

git config user.name "Numele ales"
git config user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --get user.name
git config --get user.email

Ultimele două comenzi trebuie să arate valorile alese de tine. Primele două nu afișează de obicei nimic când reușesc. Fără --global, configurația se aplică numai repository-ului curent. Această variantă este potrivită și pe calculatorul personal.

Opțional: configurare globală pe un cont personal al sistemului de operare

Folosește această variantă numai dacă ești singurul utilizator al contului din sistemul de operare. Ea se aplică repository-urilor acelui utilizator, dacă nu au o configurare locală care o înlocuiește. Înlocuiește exemplele:

Unde se copiază: în terminalul VS Code.

git config --global user.name "Numele ales"
git config --global user.email "ADRESA_EMAIL_ALEASA_EXACT"
git config --global --get user.name
git config --global --get user.email

Pe un cont de laborator comun nu folosi --global: ai schimba identitatea implicită și pentru ceilalți utilizatori.

4 · Alege un loc pentru copia locală

Creează un director părinte ușor de regăsit, de exemplu Documents/BTI. La clonare îl vei selecta, iar Git va crea în el directorul proiectului. Nu alege o locație temporară care se șterge la ieșirea din cont.

Nu inițializa acum un repository gol și nu clona peste un director deja folosit. La S05 vei crea pe GitHub propria copie din template-ul indicat și vei clona adresa copiei tale. Template-ul este repository-ul de pornire al grupei; copia ta va păstra schimbările tale.

Cum deosebești directorul părinte de directorul proiectului

Dacă ai ales Documents/BTI și repository-ul se numește bti-byte-lab-xx, copia va fi în Documents/BTI/bti-byte-lab-xx. În VS Code vei deschide acest ultim director, cel care conține PROJECT, GUIDES și START.html. Deschiderea directorului părinte poate ascunde sau încurca starea Git a proiectului.
