Eight data bits

The input is a decimal integer u from 0 to 255 inclusive. Leading and trailing spaces are ignored; leading zeros are accepted. Empty input, text, negatives, fractions and 256 are rejected. The eight binary positions have weights 128, 64, 32, 16, 8, 4, 2, 1.

One hexadecimal digit represents four bits because 16 = 2⁴. Therefore a byte needs exactly two hexadecimal characters, including a leading zero where required. Digits 10–15 are A–F. For example, 5 → 00000101 → 05 and 255 = 15 × 16 + 15 → FF.

For eight-bit two’s complement, interpret the same pattern as s = u for 0 ≤ u < 128, or s = u − 256 for 128 ≤ u ≤ 255. The range is −128 to 127. The leftmost bit has weight −128 in this interpretation; the stored bits do not change.

One separate parity bit

Let k count the 1 bits in the eight data bits. Append a numeric bit p at the right. A · even: p = k % 2, making k + p even. B · odd: p = 1 − (k % 2), making k + p odd.

DataCount kA · even pB · odd p
3 · 00000011201
7 · 00000111310

The transmitted display has nine bits: eight data bits plus a separate check bit. A single bit flip changes parity; any odd number of flips does so. An even number can preserve it. A parity check does not locate or correct the error.

Git actions and where the result exists

ActionResult and useful check
SaveWrites a file in your local folder. Reload the browser to use saved code.
DiffShows the changed content. git diff shows unstaged changes.
StageSelects the content of the next commit. git diff --cached shows that selection.
CommitRecords the staged version in local Git history. It is not published yet.
PushSends local commits to origin, normally your own GitHub repository.
CloneCreates a local working copy and Git history from the remote URL.
IssueDescribes a problem, observations and a hypothesis in your own repository.
BranchNames the separate line on which you make a repair.
Pull requestExplains a branch change proposed for integration into main.
Merge then pullMerge integrates on GitHub; git pull --ff-only updates local main afterwards.

origin is the remote’s name; main is the main branch in this project. If you edit a file after staging it, stage the new content again before committing.

git status checks branch and local changes; git remote -v checks the remote URL; git branch --show-current checks the branch; git rev-parse HEAD prints the full current commit identifier. A clean working tree alone does not prove that you pushed.

Investigation, reproduction and assessment

Investigation: own hypothesis → one AI claim or prepared response → predicted test result → observed result → conclusion. Test the point where a rule changes and rerun previously correct cases. One counterexample contradicts a claim that something works for every valid input; a few passing examples do not establish such a universal claim.

Reproduction: finish and push → clone into a different folder → check main, clean status and the same full SHA → open the fresh clone’s HTML files → rerun the reported tests. Put the final SHA in Moodle after the last commit and push, not inside a file belonging to that commit.

Quizzes: individual, no AI or classmates, this reference allowed. Q05: 10 minutes and maximum 0.20 real points; Q06: 10 minutes and 0.30; Q07: 15 minutes and 0.50. Total maximum: one real point. The final online-text assignment is compulsory and ungraded.
