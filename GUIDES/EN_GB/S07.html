2. Derive the parity bit from the rule

Let k be the number of 1 bits in the eight data bits and p the extra bit, either 0 or 1. A · even: the total k + p must be even. B · odd: the total must be odd.

InputData bitsCount kA · even bit and wordB · odd bit and word
3000000112p = 0 → 000000110p = 1 → 000000111
7000001113p = 1 → 000001111p = 0 → 000001110

For input 3, the data already contains two 1 bits. Adding 0 keeps an even total; adding 1 makes it odd. For input 7, the three existing 1 bits require the opposite choices.

k % 2 is the remainder after division by 2: 0 for an even count and 1 for an odd count. Therefore the even parity bit is k % 2; the odd parity bit is 1 − (k % 2). The extra bit is appended on the right and is separate from the byte’s signed interpretation.

What a parity check can and cannot detect

Use the A word for input 3: 000000110, which contains two 1 bits. Flip the leftmost bit to obtain 100000110: the total becomes three, so even parity detects a mismatch. Flip the first two bits instead to obtain 110000110: the total becomes four and remains even, so this two-bit change is not detected.

Every odd number of flips changes parity. An even number can preserve it. This check cannot identify which bit changed or correct the data; matching parity is not proof that no error occurred.
