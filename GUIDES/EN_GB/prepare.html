Check the tools before we begin

You need Git, VS Code, a browser, your own GitHub account and access to our Moodle course. Git manages versions; VS Code is the editor through which we use it; GitHub stores the remote repository. Having a GitHub account does not mean Git is installed.

On a prepared laboratory computer, use the installed tools. On your own computer, use the official VS Code download and Git installation instructions for your operating system. If a managed computer requires administrator access, tell us before class so the installation can be prepared.

No Node.js, Python, Live Server extension, compiler or web server is needed for this project. We open its HTML files directly.

Where: VS Code → Terminal → New Terminal. Do: run the following command. Check: text beginning with git version. Why: VS Code’s Git controls need this local installation.

Paste into: VS Code terminal · any folder

git --version
Git is not recognised or not found

Close all VS Code windows, reopen VS Code and repeat the command. If it still fails, check the installation and whether Git is available to other applications. On a laboratory computer, report the missing installation; do not copy executables around or spend the whole seminar reinstalling software.

Use your own account in both the browser and VS Code

  1. Open GitHub in the browser. Check the account menu: it must be your own account.
  2. Open Moodle and locate our BTI course. This is where we will supply the real template and quiz links.
  3. If available, check Gemini. If access is blocked or limited, the prepared response provides the S06 investigation.
  4. When VS Code later asks to authenticate with GitHub, read the browser authorisation and select your own account.

Check: the owner shown when creating your repository is you; a push must also authenticate as an account allowed to write to it. A browser session and a stored Git or VS Code session can belong to different accounts.

On a shared operating-system account, use the session arrangement prepared for the laboratory. Setting a commit author does not remove stored GitHub credentials. Signing out of one browser tab alone does not guarantee that VS Code or Git has forgotten another account. If the wrong account appears, stop before creating or pushing and tell us which account is displayed.

Do not put passwords, recovery codes or access tokens in code, README.md, an AI prompt or a Moodle record. Follow the normal interactive authentication when offered; do not improvise a token-sharing route.

Prepare the author name recorded in your commits

A commit records an author name and email. These are labels in Git history, not your GitHub login. Choose the values deliberately because they can become visible in a shared repository.

  1. In GitHub, open Settings → Emails. If you prefer to keep your personal email private, copy the exact noreply address supplied for your account. Do not invent it from your username.
  2. Choose the author name you will use and keep both values ready.
  3. After cloning in S05, configure them only for your repository using the commands below.

Where: the terminal in your own cloned repository, after S05 creates it. Replace both example values before running, keeping the quotation marks.

Paste into: VS Code terminal · repository root

git config user.name "Your chosen name"
git config user.email "PASTE_YOUR_EXACT_CHOSEN_EMAIL_HERE"
git config --get user.name
git config --get user.email

Check: the last two lines print your chosen name and email. Successful setting commands normally print nothing. Why: repository-specific settings avoid changing another student’s author on a shared account. These commands do not sign you in to GitHub.

I already configured Git on my own computer

If the operating-system account is yours alone, existing global settings may already be suitable. Check the effective values inside your clone with git config --get user.name and git config --get user.email. You may still set the local values above. Do not run global author-setting commands on a shared laboratory account.

Choose a working folder you can find again

Where: File Explorer on Windows or Finder on macOS. Create a parent folder such as Documents/BTI. At S05, VS Code will create your repository folder inside it.

Choose a location that will survive until the next seminar. If laboratory files are removed at logout, ask which location and recovery method our class uses. Your GitHub copy can restore committed and pushed work; it cannot restore a file you only saved locally.

Do not run git init here and do not create an empty repository in advance. We will create a repository from the course template, then clone that existing remote. The parent folder is just a place to keep it.

File names do not show .html or .js

Use VS Code’s Explorer to see the actual names. On Windows, File Explorer’s file-name-extension option can also show them. Opening index.html in the VS Code editor shows code; opening the same file in your browser runs the interface.
